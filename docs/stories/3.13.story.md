## Objetivo

Substituir a elicitação mecânica do `*prd` (perguntas numeradas sobre squads, stack, arquitetura) por um fluxo conversacional que chegue ao mesmo resultado técnico de forma natural — especialmente no modo CREATE, quando o usuário ainda não tem nenhum escopo e não sabe o que o Kairos espera dele.

---

## Contexto

O `*prd` atual faz 6 perguntas estruturadas em sequência ("Pergunta 1 — O que é o Kairos?", "Pergunta 2 — Arquitetura geral"...). O problema é que:

1. O usuário não pensa em termos de "squads" ou "arquitetura" — ele pensa em objetivos e problemas
2. A pergunta "O que é o Kairos?" foi corrigida (story 3.7) mas o padrão geral ainda é mecânico
3. Uma instância nova com scope vazio deve ser onboardada de forma amigável, não formulariada
4. O escopo técnico do framework já vive em `.kairos-core/docs/scope.md` — `docs/scope.md` é só sobre o contexto e objetivos do usuário

O resultado técnico (arquivo `docs/scope.md` com seções definidas) deve ser o mesmo — só o caminho até lá muda.

---

## Critérios de Aceite

### Modo CREATE — Elicitação conversacional

- [ ] `kairos-prd.md` modo CREATE substituído por uma abertura em linguagem natural: uma única pergunta aberta que convida o usuário a descrever o que está construindo e para quê — sem listar squads, arquitetura ou stack de antemão
- [ ] A partir da resposta do usuário, `@kairos` conduz perguntas de follow-up apenas para o que está faltando — sem perguntar o que já foi respondido voluntariamente
- [ ] Se o usuário menciona "prospecção", "leads", "e-mails" → @kairos infere o domínio e confirma em vez de perguntar do zero
- [ ] Se o usuário é vago → @kairos faz no máximo 2-3 perguntas adicionais antes de propor um rascunho para ajuste
- [ ] A stack técnica (Node.js, tsx, SDK) é inferida do `package.json` e `core-config.yaml` — não perguntada ao usuário, a menos que divergente
- [ ] Squads ativos são lidos de `core-config.yaml` → `agents.squads` e confirmados com o usuário ("Vi que você tem o squad X ativo — quer incluir no escopo?"), não perguntados do zero
- [ ] Ao final da conversa, `@kairos` apresenta um rascunho completo do `docs/scope.md` antes de escrever, com uma única pergunta: "Ficou bom ou quer ajustar alguma coisa?"

### Modo UPDATE — Mais direto, menos formulário

- [ ] `kairos-prd.md` modo UPDATE mantém o menu de seções atual, mas a linguagem de cada opção é simplificada — sem "Pergunta N — " como prefixo
- [ ] Se o usuário já descreveu o que quer mudar ao chamar `*prd` (ex: `*prd adicionar novo squad`), o @kairos pula o menu e vai direto à elicitação da mudança

### Resultado técnico preservado

- [ ] O arquivo `docs/scope.md` gerado pelo novo fluxo mantém a estrutura canônica definida em `kairos-prd.md` (seções: foco da instância, arquitetura, squads, objetivos, restrições, stack, change log)
- [ ] Versão e Change Log do `docs/scope.md` são atualizados normalmente após escrita

---

## Fora de Escopo

- Mudar o formato/estrutura do `docs/scope.md` gerado — o conteúdo muda, não o schema
- Reescrever o modo UPDATE do zero — só ajustar a linguagem
- Integrar com sistemas externos para inferir mais contexto além de `package.json` e `core-config.yaml`
