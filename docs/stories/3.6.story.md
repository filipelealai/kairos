# Story 3.6 — Executor @kairos para Instâncias: *implement, src/ e Modelo de Autoridade

**Epic:** 3 — Governança e Versionamento
**Status:** Draft
**Complexidade:** G
**Criada por:** @kairos
**Data:** 2026-04-15

---

## Objetivo

Formalizar @kairos como executor de stories `type: instance` (squads, workers, agentes e scripts associados), introduzir o comando `*implement` dedicado a essa execução, clarificar que todo `src/` (tools e agents) é domínio do @kairos — não do Claude Code plain — e atualizar a matriz de autoridade (L1) e o ciclo de vida de stories (L3) para refletir o modelo correto. Stories `type: kairos-core` continuam sendo implementadas por Claude Code plain; @kairos governa, exibe o aviso e revisa.

---

## Contexto Arquitetural

O princípio constitucional 10 diz "@kairos não substitui o trabalho **operacional** dos squads — governa, não executa." "Operacional" = o que os squads fazem em seu domínio (analisar leads, gerar e-mails). Isso nunca impediu @kairos de **implementar a estrutura** dos squads — aliás, `*new-squad` já é EXCLUSIVO de @kairos. A lacuna atual é que a `story-lifecycle.md` e a seção "Quem Constrói o Kairos" em `agent-authority.md` não distinguem entre implementação de framework e implementação de instâncias, tratando Claude Code como executor universal. Esta story corrige essa omissão.

---

## Critérios de Aceite

### Modelo de Autoridade (L1)

- [ ] `agent-authority.md` — nova seção adicionada: "Quem Implementa Instâncias":
  - Stories `type: instance` → @kairos é o executor via `*implement`
  - Stories `type: kairos-core` → Claude Code plain é o executor (permanece como hoje)
  - Todo `src/` (tools e agents): gerenciado por @kairos — `src/tools/*.ts` como infraestrutura de instâncias (L2 no manifesto, authority de @kairos), `src/agents/*.ts` como scripts de instância implementados via `*implement`
  - Claude Code plain não escreve arquivos em `src/` sob o novo modelo

### Ciclo de Vida (L3)

- [ ] `story-lifecycle.md` — nova seção "Executor por Tipo de Story":
  - `type: instance`: @kairos permanece ativo durante toda a implementação; usa `*implement`; Execution Log assinado "@kairos (via *implement)"
  - `type: kairos-core`: Claude Code plain implementa (sem persona ativa); @kairos governa (exibe aviso por story 3.5), revisa via `*review` e move para Done

### *implement — Nova Task e Comando

- [ ] Nova task `.kairos-core/tasks/kairos-implement.md` criada com os seguintes comportamentos:
  - Argumento `{story-id}` opcional: se omitido, lista stories `type: instance` com status Draft ou In Progress e pede ao usuário que escolha
  - Recusa explícita para stories `type: kairos-core`: "Esta story modifica o framework (type: kairos-core) — implementação é por Claude Code plain. Saia do modo @kairos para implementar."
  - Move story Draft → In Progress ao iniciar; registra no Change Log da story
  - Lê Objetivo, ACs e arquivos esperados da story; implementa arquivo por arquivo
  - Ao concluir: adiciona seção `## Execution Log` (executor: "@kairos via *implement"), move para In Review
  - Exibe: "✅ Implementação concluída. Rode `*review {id}` para validar e gerar o gate."
- [ ] Gate de `*review` para stories `type: instance` implementadas via `*implement` inclui campo `self_reviewed: true` e nota: "Story implementada e revisada pelo mesmo agente — validação estrutural (ACs, arquivos), não independente."

### Integração com *new-squad e *new-worker

- [ ] `kairos-new-squad.md` — ao final da auto-criação de story (vide story 3.5), oferecer: "Story {id} criada em Draft. Implementar o squad agora? (s = *implement {id}, n = fazer depois)"
  - Se s: executar `*implement {id}` inline na mesma sessão
- [ ] `kairos-workers.md` — se o worker criado via `*workers new` gerar uma story associada (tipo: instance), oferecer a mesma sugestão de `*implement` ao final

### Persona e Help

- [ ] Persona `kairos.md` — comando `*implement [{story-id}]` adicionado:
  - visibility: [full, quick, key]
  - description: "Implementar story type: instance — move Draft→InReview, executa ACs, adiciona Execution Log"
  - Recusa para type: kairos-core
- [ ] `kairos-help.md` — `*implement` adicionado na Seção 2 (comandos); Fluxo de instâncias (④ e ⑤) atualizado: `*new-squad` → story criada → `*implement` → `*review` → `*pre-push` → `*push`; Seção "Quando NÃO usar @kairos" revisada (antes dizia que @kairos não executa; agora: @kairos não faz trabalho operacional dos squads, mas implementa instâncias)

### Versão

- [ ] Esta story requer bump **MAJOR** (2.0.0 → 3.0.0): mudança em `agent-authority.md` (L1) — adição de seção que estende o modelo de autoridade
- [ ] Justificativa registrada no CHANGELOG: "Extensão do modelo de autoridade: @kairos formalizado como executor de stories type: instance; Claude Code plain reservado para type: kairos-core; todo src/ sob domínio @kairos"
