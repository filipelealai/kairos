## Objetivo

Tornar a versão semver do Kairos materializada como **tag Git** no remoto público (`filipelealweb/kairos` `main`), automaticamente após cada push bem-sucedido. Sem isso, `*update` (Story 7.3) não consegue puxar versões estáveis em vez de HEAD. A fonte autoritativa da versão continua sendo `CHANGELOG.md` (já validado pelo `*pre-push` existente). Como ação one-shot dentro desta story, criar tags retroativas para todas as versões já no CHANGELOG sem tag correspondente.

---

## Critérios de Aceite

- [x] `squads/ops/tasks/push-dual.md` estendido: após push bem-sucedido para `origin/main`, cria tag `v{versão extraída do topo do CHANGELOG.md}` apontando para o commit recém-pushado, e pusha a tag para `origin`
- [x] Validação cruzada: a versão extraída do CHANGELOG deve bater com `core-config.yaml.version` — se divergem, HALT antes do tagging
- [x] Se a tag já existe no remoto: HALT com mensagem clara ("bump esquecido?") e não pusha
- [x] Guard de Git no início de `*version`, `*pre-push` e `*push` (e `push-dual`): se `git` não está detectado/instalado, HALT e oferece instalar (instruções por SO + opção de auto-install via winget/brew/apt com confirmação)
- [x] Backfill one-shot executado como parte desta story: implementador lê o `CHANGELOG.md`, parea cada versão com o commit correspondente no histórico de `origin/main`, cria as tags retroativas localmente e pusha todas com `git push --tags`. Resultado verificável via `git ls-remote --tags origin`
- [x] Documentação do procedimento de backfill incluída no Execution Log (não vira task permanente)
- [x] Tasks `kairos-version-bump.md`, `kairos-pre-push.md` e `kairos-push.md` ganham o guard de Git mencionado acima

## Fora de Escopo

- Criação de Releases formais no GitHub (Releases ≠ tags; este escopo cria apenas tags Git)
- Tagging em `private` remote (push-dual continua sem tags no privado)
- Backfill como task permanente reutilizável — é ação one-shot

## Dependências

- Acesso de push para `filipelealweb/kairos` (público) com permissão de criar tags
- Histórico do `main` precisa estar acessível para parear versões com commits

### Decisões tomadas

- **Passo 3.5 inserido entre Passo 3 e Passo 4 do push-dual:** tagging ocorre depois do push do código mas antes de retornar para `filipe-instance` — garante que a tag aponta para o commit recém-pushado em `main`
- **Tag "já existe" é HALT não-fatal:** o push do código já ocorreu com sucesso; o HALT é apenas um aviso ("bump esquecido?") que não desfaz o push
- **Backfill não vira task permanente:** documentado apenas no Execution Log, conforme escopo da story
