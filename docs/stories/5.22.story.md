## Objetivo

Remover `package.json`, `package-lock.json` e `tsconfig.json` do repo público (`origin/main`), onde são artefatos de instância que não pertencem ao framework, e garantir que o `push-dual` nunca os reintroduza — estabelecendo limpeza definitiva da fronteira instância/framework no repo público.

> **Bump:** PATCH — limpeza operacional + atualização de task L2 (`push-dual.md`).

## Critérios de Aceite

- [ ] Verificar quais dos 3 arquivos (`package.json`, `package-lock.json`, `tsconfig.json`) estão presentes em `origin/main` — documentar estado encontrado no Execution Log
- [ ] Para cada arquivo presente em `origin/main`: removê-lo via commit explícito direto em `main` (operação pontual — não via push-dual normal; usar `git checkout main`, `git rm`, `git commit`, `git push origin main`)
- [ ] Confirmar que nenhuma etapa existente do `push-dual.md` (Passos 2a, 2b, 3) inclui explicitamente `package.json`, `package-lock.json` ou `tsconfig.json` em qualquer `git checkout` — documentar a verificação no Execution Log
- [ ] `.kairos-core/manifest.yaml` notas: confirmar que os 3 arquivos já constam como "metadados da instância" (a nota atual menciona `package.json`, `tsconfig.json` — verificar se `package-lock.json` também está coberto); se não, adicionar
- [ ] `package.json` da instância: `description` atualizada de "agente pessoal poderoso de automação, análise e gestão de tarefas" para texto neutro que descreve o projeto de instância sem ser pessoal (ex: "Kairos instance — TypeScript agent scripts and squad tooling")
- [ ] `package.json`: `@anthropic-ai/sdk` movido de `dependencies` para `devDependencies` (é usado apenas por scripts de agentes user-owned rodados com `tsx`, não por nenhum runtime de produção do framework)

## Fora de Escopo

- Atualização de conteúdo de `package.json` além de `description` e mover `@anthropic-ai/sdk`
- Mudanças em `tsconfig.json` (ajuste de estrutura multi-stack é decisão futura)
- Remoção de outros arquivos de instância que possam estar em `main` além dos 3 citados
- Discussão sobre se o Kairos deve ou não ter `package.json` no futuro como CLI instalável (coberto por candidata 5.26)
