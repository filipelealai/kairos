---

## Objetivo

Permitir que membros do time compartilhem squads completos (com agentes, tasks, memory, personas, vars de ambiente declaradas e dependências externas como CLIs) em **um único arquivo distribuível** — sem depender de Git como meio. Usuário A roda `*export-squad`, envia o arquivo por qualquer canal (e-mail, Drive, pendrive), usuário B roda `*import-squad` e tem o squad operacional na sua instância.

---

## Critérios de Aceite

- [ ] Nova task `.kairos-core/tasks/kairos-export-squad.md` que empacota um squad em arquivo único `kairos-squad-{nome}-{versão-framework}.tar.gz` ou `.zip` (o usuário escolhe) contendo:
  - Pasta `squads/{nome}/` inteira
  - Tasks específicas do squad em `.kairos-core/tasks/{nome}-*.md` e `.kairos-core/tasks/{agent-id}-*.md` referenciadas
  - `MEMORY.md` dos agentes em `.kairos-core/agents/{agent}/`
  - Personas em `.claude/commands/kairos/agents/{agent}.md` referenciadas pelo squad
  - Manifesto local do export listando tudo incluído + versão de framework de origem + checksum
  - Patch de vars de ambiente delimitado (`# --- squad:{nome} - START ---` / `# --- END ---`) gerado a partir das integrations declaradas em `squad.yaml`
  - Manifesto de dependências externas (extraído de `squad.yaml.external_dependencies`)
- [ ] Squads ativos desta instância ganham campo `external_dependencies` em `squad.yaml`:
  - `cold-prospecting`: dependências (n8n, etc. — implementador valida)
  - `sales-pipeline`: declara `trello-cli` com nome, finalidade, comando de detecção (`which trello-cli` / `Get-Command trello-cli`), instruções de instalação por SO
  - `client-onboarding`: dependências (implementador valida)
- [ ] Nova task `.kairos-core/tasks/kairos-import-squad.md` com fluxo:
  1. Recebe path do arquivo
  2. Valida checksum e versão de framework — se major divergir, alerta e pede confirmação para prosseguir
  3. Se squad de mesmo nome já existe na instância, oferece três opções claras:
     - **Atualizar** (recomendado): substitui apenas arquivos do squad cujo conteúdo diverge, preservando o resto. Apresenta diff resumido antes de aplicar
     - **Sobrescrever** (destrutivo): apaga o squad existente e reescreve do export (com confirmação explícita pela natureza destrutiva)
     - **Renomear**: importa com novo nome (sufixo automático ou input do usuário)
  4. Aplica patch de vars no `.env.example` da instância **fora** das seções `<!-- KAIROS-MANAGED-... -->` (área user-owned do arquivo)
  5. Adiciona imports do squad em `CLAUDE.md` na seção user-owned "Squads ativos"
  6. Valida cada `external_dependency` do squad: se faltar, mostra instruções específicas por SO; oferece auto-install via gerenciador (winget/brew/apt) com confirmação. Não instala silenciosamente
  7. Roda `*doctor` ao final
- [ ] Persona `@kairos` ganha comandos `*export-squad` e `*import-squad`
- [ ] `kairos-doctor.md` ganha check de `external_dependencies` declaradas pelos squads ativos — warning quando dependência faltando
- [ ] Manifesto registra novas tasks como `owned_files`
- [ ] Smoke test:
  - Em uma instância A com `sales-pipeline` configurado, rodar `*export-squad sales-pipeline` → gerar arquivo
  - Em instância B (limpa, mesma versão framework), rodar `*import-squad ./kairos-squad-sales-pipeline-X.Y.Z.tar.gz`
  - Verificar: pasta squad presente, tasks copiadas, persona disponível, `.env.example` com bloco de vars do squad fora das seções managed, `external_dependencies` validadas (warning se trello-cli faltando)
  - `*doctor` PASS (com warning aceitável se dependência opcional ausente)

## Fora de Escopo

- Versionamento independente de squads (squads herdam a versão do framework de origem)
- Marketplace ou registry de squads — distribuição é por arquivo direto
- Resolução automática de conflitos de personas (se duas pessoas exportam squads que dependem da mesma persona com versões diferentes) — fica como follow-up
