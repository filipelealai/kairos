## Objetivo

Incorporar SHA sync do `manifest.yaml` como parte natural do processo de `*pre-push` e `*version`, eliminando o drift acumulado desde v2.0.0 e garantindo que o manifesto se mantenha atual como efeito colateral automático dos fluxos já existentes.

## Contexto

O `manifest.yaml` foi criado na story 5.1 com SHAs calculados em v2.0.0. O framework evoluiu para v3.1.1 e `*doctor` reporta SHA drift em praticamente todos os `owned_files`. Os SHAs representam o estado canônico de cada arquivo framework na versão vigente — precisam ser mantidos atuais.

**Princípio:** nenhum comando novo, nenhum passo extra para o usuário. SHA sync é uma responsabilidade que cabe naturalmente a `*pre-push` (que já faz versioning como parte do seu processo) e a `*version` (bump manual explícito).

---

## Critérios de Aceite

- [ ] `kairos-pre-push.md` atualizado: inclui passo de SHA sync — para cada `owned_files[*]` em `manifest.yaml`, calcula SHA atual do arquivo e atualiza o campo `sha256` se divergir; executa antes do commit final do pre-push
- [ ] `kairos-version-bump.md` atualizado: inclui SHA sync como parte do processo de bump — mesmo mecanismo, executado após atualizar `version` e antes de fechar
- [ ] One-time refresh executado: todos os SHAs em `manifest.yaml` atualizados para o estado atual (v3.1.1)
- [ ] `*doctor` Check 9 retorna zero WARNs de SHA drift após one-time refresh
- [ ] `manifest.yaml` commitado com SHAs atualizados como parte desta story
