## Objetivo

Tornar o scaffolding de agentes data-driven: a definição em `squads/{squad}/agents/{id}.yaml` (fonte de verdade) gera automaticamente a persona em `.claude/commands/kairos/agents/{id}.md` durante o `*new-squad`, eliminando a criação manual de personas como AC da story de implementação.

## Contexto

Hoje `*new-squad` cria `squads/{squad}/agents/{id}.md` (lightweight — apenas YAML frontmatter com referência) mas não cria a persona em `.claude/commands/kairos/agents/`. Essa criação fica como AC manual na story de implementação gerada pelo scaffolding. A consequência é que, após `*new-squad`, o agente não é ativável até a story de implementação ser executada.

A proposta é tornar o formato de definição canônico (`.yaml`) rico o suficiente para gerar uma persona funcional durante o scaffolding, tornando o agente imediatamente ativável mesmo antes da story de implementação adicionar comportamentos específicos de domínio.

## Critérios de Aceite

- [x] `.kairos-core/templates/squad-template/agents/agent-id.yaml` criado com schema canônico rico (id, name, icon, whenToUse, persona_profile com tone/greeting/signature_closing, commands com visibility e description, outputs, handoffs)
- [x] `kairos-new-squad.md` inclui passo de geração da persona em `.claude/commands/kairos/agents/{id}.md` a partir de `squads/{squad}/agents/{id}.yaml`, usando Markdown template embutido na task
- [x] Persona gerada é funcionalmente completa: contém `activation-instructions`, greeting derivado do `persona_profile`, lista de comandos, identidade e `signature_closing`
- [x] Agentes existentes do squad `cold-prospecting` migrados de `.md` para `.yaml` em `squads/cold-prospecting/agents/` com schema novo
- [x] `kairos-doctor.md` inclui check de drift: `squads/*/agents/*.yaml` sem persona correspondente em `.claude/commands/kairos/agents/` → WARNING
- [x] `kairos-new-squad.md` não inclui mais o AC "criar persona em `.claude/commands/`" nas stories de implementação geradas (persona já existe após scaffolding)

## Fora de Escopo

- Regeneração automática de personas quando o YAML é editado depois do scaffolding (update incremental — story futura)
- CLI externo (`npx kairos generate`) para geração de personas fora do Claude Code
- Migração de agentes de outros squads além de `cold-prospecting`

### Decisões tomadas

- **`agent-id.md` removido do template em vez de mantido:** o `.yaml` agora é a fonte de verdade canônica; manter os dois em paralelo criaria ambiguidade sobre qual é normativo.
- **Migração cold-prospecting extraída das personas existentes:** os `.yaml` foram criados com os dados da persona real (`.claude/commands/kairos/agents/`) em vez do `.md` antigo (que tinha info mínima), garantindo que o `.yaml` seja verdadeiramente rico e capaz de regenerar a persona.
- **Template embutido na task em vez de arquivo externo:** o Markdown template da persona fica inline em `kairos-new-squad.md` para que a task seja autossuficiente (sem dependência de arquivo de template separado que poderia ficar desatualizado).
- **Check 3a separado do check 3 no doctor:** o check 3 cobre agentes registrados no `core-config.yaml`; o 3a cobre `.yaml` no filesystem — são complementares e detectam drift em direções diferentes.
