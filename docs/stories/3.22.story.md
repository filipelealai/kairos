## Objetivo

Adicionar o argumento `all` ao comando `*implement` existente para implementar em massa todas as stories `type: instance` em Draft ou In Progress, com review automático de cada uma e relatório consolidado ao final. O usuário só é consultado antes do pre-push.

## Contexto

Hoje, `*implement {id}` opera sobre uma única story por vez. Quando o backlog acumula várias stories `type: instance` já criadas, o usuário precisa executar `*implement` e `*review` manualmente para cada uma. O argumento `all` automatiza essa iteração sem mudar o processo — apenas o executa em massa.

**Escopo:** apenas `type: instance`. Stories `type: kairos-core` são ignoradas (instruir o usuário a usar `*yolo` para essas).

## Critérios de Aceite

- [x] AC1: `*implement all` detecta todas as stories `type: instance` com status `Draft` ou `In Progress` em `docs/stories/`
- [x] AC2: Antes de iniciar, exibe lista das stories que serão implementadas e aguarda confirmação do usuário (única confirmação, não por story)
- [x] AC3: Implementa cada story sequencialmente usando o mesmo fluxo de `*implement {id}` — Execution Log adicionado a cada uma
- [x] AC4: Após implementar cada story, executa `*review {id}` automaticamente — gate salvo em `docs/qa/gates/`
- [x] AC5: Story com gate BLOCK não interrompe o processo — as demais continuam sendo implementadas; a story bloqueada é marcada como pendente no relatório
- [x] AC6: Após processar todas as stories, exibe relatório consolidado: para cada story, status de implementação (OK/BLOCK/ERRO) + veredicto do gate + arquivos modificados
- [x] AC7: Para antes de `*pre-push` — exibe o relatório e aguarda confirmação explícita do usuário para prosseguir com o pre-push
- [x] AC8: Stories `type: kairos-core` encontradas no backlog são listadas no relatório como "ignoradas — usar *yolo" mas não interrompem o processamento das demais
- [x] AC9: Se nenhuma story elegível for encontrada, exibir mensagem clara ("Nenhuma story type: instance em Draft ou In Progress")

## Fora de Escopo

- Implementação paralela (mantém processamento sequencial)
- `*implement all` para `type: kairos-core` (coberto por `*yolo`)
- Pre-push automático (o usuário confirma antes)

### Decisões tomadas

- **Seção inline vs task separada:** optou-se por estender `kairos-implement.md` com uma seção `[Modo All]` em vez de criar uma task `kairos-implement-all.md` separada — o fluxo all reutiliza exatamente os Passos 1–6 do fluxo single, então separar criaria duplicação e violaria o princípio IDS.
- **Confirmação única antes de iniciar vs por-story:** AC2 define uma confirmação única. Isso foi implementado no All-Passo 2; não há confirmações intermediárias por story (exceto as já previstas no fluxo single para dependências não concluídas ou ACs ambíguos).
- **BLOCK não interrompe:** AC5 é explícito — gate BLOCK registra a story como pendente mas o loop continua. Implementado no All-Passo 3 com categorias `OK/BLOCK/ERRO`.
- **Pre-push não automático:** AC7 garante que `*pre-push` nunca é executado sem confirmação explícita no Modo All — mesmo que `yolo_active = true`. A confirmação no relatório final é a barreira.
