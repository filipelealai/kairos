## Objetivo

Fechar a lacuna de sincronização entre `filipe-instance` e `main`: arquivos de framework ausentes no repo público (`CHANGELOG.md`, `README.md`) e arquivos mistos cujas seções framework não chegam ao `main` (`CLAUDE.md`, `settings.json`, `core-config.yaml`).

## Contexto

O push-dual atual sincroniza apenas `owned_files` inteiros. Três categorias de problema persistem:

1. **Full files ausentes** — `CHANGELOG.md` e `README.md` não estão no manifesto e nunca chegam ao `main`.
2. **Mixed Markdown** — `CLAUDE.md` tem blocos `KAIROS-MANAGED-START/END` mas push-dual não os extrai para `main`. Foi deletado manualmente como contingência (commit `93d6942`).
3. **Mixed YAML/JSON** — `core-config.yaml` expõe `project.owner` e `agents.squads` (dados de instância) em `main`; `settings.json` usa `owned_keys` no manifesto mas não tem mecanismo de sync nem marcadores de seção, quebrando brownfield.

## Critérios de Aceite

### Track 1 — Full files

- [ ] `CHANGELOG.md` adicionado a `manifest.yaml → owned_files` com `layer: L3`
- [ ] `README.md` adicionado a `manifest.yaml → owned_files` com `layer: L3`
- [ ] push-dual (Passo 2) sincroniza os dois via `git checkout filipe-instance -- <path>` como qualquer outro `owned_file`

### Track 2a — CLAUDE.md (Mixed Markdown)

- [ ] push-dual extrai blocos `<!-- KAIROS-MANAGED-START: {nome} --> ... <!-- KAIROS-MANAGED-END: {nome} -->` do CLAUDE.md de `filipe-instance` e constrói a versão de `main` contendo apenas esses blocos
- [ ] Conteúdo user-owned (seções fora dos markers) não chega ao `main`
- [ ] `CLAUDE.md` restaurado em `main` com as seções framework (base: conteúdo de `93d6942~1`, atualizado para o estado atual dos markers)

### Track 2b — settings.json (Mixed JSON)

- [ ] `settings.json` recebe marcadores JSONC: `// KAIROS-MANAGED-START: hooks` e `// KAIROS-MANAGED-END: hooks` delimitando a seção de hooks do Kairos
- [ ] Manifesto migra `settings.json` de `owned_keys: [hooks]` para `owned_sections: [hooks]` (alinhando com o padrão de CLAUDE.md)
- [ ] push-dual extrai a seção entre os markers JSONC e constrói a versão de `main` contendo apenas o conteúdo Kairos-owned
- [ ] Brownfield-safe: markers permitem que instalação futura adicione/atualize apenas a seção Kairos sem sobrescrever hooks ou configs pré-existentes do usuário
- [ ] Versão de `main` de `settings.json` contém apenas a seção Kairos (não expõe configs de instância)

### Track 2c — core-config.yaml (Mixed YAML — Opção A)

- [ ] push-dual gera versão de `main` de `core-config.yaml` com seções `framework`, `runtime`, `versioning` e campos top-level (`version`, `installedAt`, `updatedAt`) intactos
- [ ] Seção `project` aparece em `main` com placeholders: `owner: "{owner}"`, `name: "{project-name}"`, `scope: personal`
- [ ] Seção `agents` aparece em `main` com placeholder: `squads: {}` (sem dados de instância)
- [ ] Manifesto mantém `owned_keys: [framework, runtime, versioning]` para `core-config.yaml` (semântica correta — a geração de placeholders é comportamento do push-dual, não um novo tipo de ownership)

### Track 3 — push-dual atualizado

- [ ] `squads/ops/tasks/push-dual.md` documenta Passo 2 com dois sub-passos explícitos:
  - **Passo 2a** — `owned_files` inteiros: `git checkout filipe-instance -- <path>` (comportamento atual, agora inclui CHANGELOG.md e README.md)
  - **Passo 2b** — arquivos mistos (`owned_sections`): geração de versão framework-only para cada arquivo (CLAUDE.md, settings.json, core-config.yaml), com instrução específica para cada um
- [ ] push-dual referencia o manifesto como fonte autoritativa para determinar quais arquivos são `owned_files` vs `owned_sections`

## Fora de Escopo

- Implementação do installer brownfield (story 5.5 futura) — esta story apenas torna `settings.json` brownfield-safe pela estrutura de markers
- Criação de novo mecanismo genérico de "template engine" — cada arquivo misto tem instrução explícita no push-dual
- Modificações no conteúdo das seções framework de `CLAUDE.md` ou `settings.json` — apenas estrutura e sync
- Branch protection em `main` (candidata 5.4 original, renomear para 5.5+)
