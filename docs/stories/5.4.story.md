## Objetivo

Fechar a lacuna de sincronização entre `filipe-instance` e `main`: arquivos de framework ausentes no repo público (`CHANGELOG.md`, `README.md`) e arquivos mistos cujas seções framework não chegam ao `main` (`CLAUDE.md`, `settings.json`, `core-config.yaml`).

## Contexto

O push-dual atual sincroniza apenas `owned_files` inteiros. Três categorias de problema persistem:

1. **Full files ausentes** — `CHANGELOG.md` e `README.md` não estão no manifesto e nunca chegam ao `main`.
2. **Mixed Markdown** — `CLAUDE.md` tem blocos `KAIROS-MANAGED-START/END` mas push-dual não os extrai para `main`. Foi deletado manualmente como contingência (commit `93d6942`).
3. **Mixed YAML/JSON** — `core-config.yaml` expõe `project.owner` e `agents.squads` (dados de instância) em `main`; `settings.json` usa `owned_keys` no manifesto mas não tem mecanismo de sync nem marcadores de seção, quebrando brownfield.

## Critérios de Aceite

### Track 1 — Full files

- [x] `CHANGELOG.md` adicionado a `manifest.yaml → owned_files` com `layer: L3`
- [x] `README.md` adicionado a `manifest.yaml → owned_files` com `layer: L3`
- [x] push-dual (Passo 2) sincroniza os dois via `git checkout filipe-instance -- <path>` como qualquer outro `owned_file`

### Track 2a — CLAUDE.md (Mixed Markdown)

- [x] push-dual extrai blocos `<!-- KAIROS-MANAGED-START: {nome} --> ... <!-- KAIROS-MANAGED-END: {nome} -->` do CLAUDE.md de `filipe-instance` e constrói a versão de `main` contendo apenas esses blocos
- [x] Conteúdo user-owned (seções fora dos markers) não chega ao `main`
- [ ] `CLAUDE.md` restaurado em `main` com as seções framework (base: conteúdo de `93d6942~1`, atualizado para o estado atual dos markers)

### Track 2b — settings.json (owned_file)

- [x] `settings.json` é 100% framework-owned — movido de `owned_sections` para `owned_files` no manifesto (L2)
- [x] push-dual sincroniza `settings.json` via `git checkout filipe-instance -- .claude/settings.json` (igual a qualquer outro owned_file)
- [x] Customizações do usuário vão em `settings.local.json` (gitignored) — separação limpa sem risco de vazamento
- [x] Versão de `main` de `settings.json` contém apenas conteúdo Kairos (sem dados de instância)

### Track 2c — core-config.yaml (Mixed YAML — Opção A)

- [x] push-dual gera versão de `main` de `core-config.yaml` com seções `framework`, `runtime`, `versioning` e campos top-level (`version`, `installedAt`, `updatedAt`) intactos
- [x] Seção `project` aparece em `main` com placeholders: `owner: "{owner}"`, `name: "{project-name}"`, `scope: personal`
- [x] Seção `agents` aparece em `main` com placeholder: `squads: {}` (sem dados de instância)
- [x] Manifesto mantém `owned_keys: [framework, runtime, versioning]` para `core-config.yaml` (semântica correta — a geração de placeholders é comportamento do push-dual, não um novo tipo de ownership)

### Track 3 — push-dual atualizado

- [x] `squads/ops/tasks/push-dual.md` documenta Passo 2 com dois sub-passos explícitos:
  - **Passo 2a** — `owned_files` inteiros: `git checkout filipe-instance -- <path>` (comportamento atual, agora inclui CHANGELOG.md e README.md)
  - **Passo 2b** — arquivos mistos (`owned_sections`): geração de versão framework-only para cada arquivo (CLAUDE.md, settings.json, core-config.yaml), com instrução específica para cada um
- [x] push-dual referencia o manifesto como fonte autoritativa para determinar quais arquivos são `owned_files` vs `owned_sections`

## Fora de Escopo

- Modificações no conteúdo das seções framework de `CLAUDE.md` ou `settings.json` — apenas estrutura e sync
- Branch protection em `main` (candidata 5.4 original, renomear para 5.5+)
