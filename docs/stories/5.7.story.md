## Objetivo

Eliminar trabalho desnecessário no Passo 2b do push-dual: arquivos mistos (`CLAUDE.md`, `core-config.yaml`) que não foram modificados desde o último commit de sync em `origin/main` não devem ser reprocessados — economizando tokens e tempo de execução.

## Contexto

O Passo 2b do push-dual extrai seções framework de arquivos mistos e os reescreve para `main` a cada push, mesmo quando o conteúdo não mudou. Para `CLAUDE.md` isso implica extrair blocos via regex; para `core-config.yaml` implica reconstruir o YAML com placeholders. Ambos são operações custosas em tokens que produzem zero diff quando os arquivos não foram tocados no ciclo.

## Critérios de Aceite

- [ ] `push-dual.md` Passo 2b inclui lógica de skip por arquivo misto: antes de reprocessar cada arquivo, verificar se ele foi modificado em `filipe-instance` desde o último commit de sync (`origin/main`) usando `git log origin/main..filipe-instance -- <path>`
- [ ] Se o comando retornar vazio (nenhum commit novo tocou o arquivo): pular o reprocessamento daquele arquivo e registrar `→ skip: sem mudança desde último sync`
- [ ] Se o comando retornar commits: reprocessar normalmente (extrair seções / reconstruir com placeholders)
- [ ] O skip se aplica independentemente a cada arquivo misto (ex: `CLAUDE.md` pode ser skipado enquanto `core-config.yaml` é reprocessado)
- [ ] Ao final do Passo 2b, exibir resumo: quantos arquivos foram reprocessados e quantos foram pulados
- [ ] O comportamento de skip não se aplica ao Passo 2a (`owned_files`) — `git checkout` de arquivo idêntico é idempotente e barato; manter como está

## Fora de Escopo

- Otimização do Passo 2a (checkout de owned_files — já é idempotente)
- Cache persistente entre sessões do estado de sync
- Detecção de mudanças parciais dentro dos blocos KAIROS-MANAGED (a granularidade é por arquivo)
