## Objetivo

Remover conteúdo semântico específico de instância das tasks `kairos-architecture.md` e `kairos-prd.md`, garantindo que o comportamento geral do framework não dependa de padrões de squads específicos.

As tasks devem operar genericamente em qualquer instância Kairos — sem assumir webhook como mecanismo de data flow, sem referenciar "Campos do Lead", sem citar `emails/` como diretório de output esperado, e sem tratar "Node.js/tsx/Anthropic SDK" como a stack padrão do Kairos.

Este é o complemento de 5.26: enquanto 5.26 trata de *como* a task descobre configuração (ler de `docs/scope.md` em vez de `package.json`), esta story trata de *o que* a task procura — removendo referências semânticas que codificam padrões de uma instância específica.

## Critérios de Aceite

### kairos-architecture.md

- [x] Passo 4 (Data Flow) não usa o label "Campos do webhook" — a verificação de alinhamento docs/código é descrita genericamente como "campos/inputs declarados no data-flow.md", sem assumir webhook como mecanismo de transporte
- [x] Passo 4 não referencia "Campos do Lead" — a seção do data-flow.md a ser lida é identificada pelo que o documento da instância declara, não por um nome de campo específico desta instância
- [x] Passo 4 não lista `data/outputs/{squad}/emails/` como diretório de output esperado — outputs são descobertos a partir do que está declarado no data-flow.md ou squad.yaml; nenhum nome de subdiretório é hardcoded
- [x] Passo 6 (Decisões Arquiteturais) não lista "(Se instância usa TypeScript) Por que tsx sem compilação?" nem "(Se instância usa n8n) Por que n8n para disparo?" como decisões-chave esperadas — apenas decisões universais ao framework permanecem na lista
- [x] Relatório (Passo 7) não inclui "Campos do webhook documentados" como item da seção `━━━ DATA FLOW ━━━` — substituído por label genérico (ex: "Inputs/campos documentados no data-flow")
- [x] `kairos-architecture.md` explicita que o Passo 4 não assume mecanismo de transporte (webhook, API, arquivo, planilha) — a comparação docs/código é genérica

### kairos-prd.md

- [x] Passo 0 trata `package.json` como leitura condicional ("se existir `package.json`..."; "se existir `pyproject.toml`..."), não como read obrigatório
- [x] Passo 2 (Stack) remove "Node.js/tsx/Anthropic SDK" como "padrão Kairos" — se nenhum arquivo de dependências existir, a stack é perguntada ao usuário em vez de assumida
- [x] Passo 2 (Inferência de domínio) remove o mapeamento explícito "prospecção/leads/e-mails → cold outreach" e "dados/relatórios → analytics" — o princípio (inferir do contexto, confirmar) é preservado, mas sem exemplos que codificam o domínio desta instância específica
