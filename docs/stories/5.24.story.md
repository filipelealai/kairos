## Objetivo

Formalizar e documentar a posição arquitetural de que o Kairos é um framework stack-agnóstico: o núcleo é markdown + YAML + CJS hooks; `src/` é user-owned e pode conter scripts em qualquer linguagem; o usuário gerencia suas próprias dependências de runtime — o Kairos apenas interage e governa, sem impor stack.

> **Bump:** MINOR — formalização de posição arquitetural no KB e em documentação pública; estabelece contrato documentado que guiará stories futuras de multi-stack.

## Critérios de Aceite

- [x] `CONTRIBUTING.md` seção "Scripts em `src/` (user-content, per-instance)": texto atualizado para explicitar que scripts podem ser TypeScript, Python ou qualquer outra linguagem — o Kairos não impõe stack; o usuário escolhe e gerencia suas dependências
- [x] `CONTRIBUTING.md` seção "Roadmap multi-stack": tabela atualizada para incluir a estrutura proposta de `src/` para quando múltiplas stacks coexistirem (`src/agents/ts/`, `src/agents/python/`, `src/tools/ts/`, `src/tools/python/`)
- [x] `.kairos-core/data/kairos-kb.md`: nova entrada adicionada com a decisão arquitetural "Framework stack-agnóstico" — incluindo: (a) o que o Kairos É (markdown + YAML + CJS), (b) o que `src/` é (user-owned, qualquer linguagem), (c) a estrutura proposta de `src/{lang}/` para multi-stack, (d) o que NÃO É responsabilidade do framework (gerenciar dependências de runtime da instância)
- [x] Qualquer referência remanescente a TypeScript como linguagem obrigatória de scripts de agente em arquivos framework-managed removida — não é requisito do framework
- [x] Verificar `kairos-doctor.md`, `kairos-architecture.md`, `agent-standards.md` e `data-flow.md` para ocorrências de TypeScript hardcoded que devam ser removidas ou adaptadas para stack agnóstica

## Fora de Escopo

- Movimentação física de arquivos existentes (`src/agents/*.ts` → `src/agents/ts/`) — isso é uma story de migração futura, separada e mais impactante
- Mudanças nos arquivos L1 (coberto por 5.25)
- Criação de scripts Python ou outro runtime — puramente documental e arquitetural
- Atualização de todas as tasks e personas que referenciam `npx tsx` (escopo demasiado amplo — stories seguintes podem cobrir por squad/task)

## Dependências

- Recomendado executar após 5.20 e 5.21 (para não duplicar edições em README e CLAUDE.md) e após 5.25 (para que o KB reflita a fundação L1 corrigida).
- Não bloqueante — pode iniciar em paralelo se as seções editadas não se sobrepuserem.
