## Objetivo

Criar o primeiro workflow de GitHub Actions do Kairos — `.github/workflows/validate-manifest.yml` — que executa, em PRs contra `main`, os mesmos checks que `@kairos *pre-push` valida localmente via `*doctor` (story 5.28): ownership, sha256 de manifest, frontmatter e sync_files. Oferece gate automático para contribuições externas sem depender do Kairos rodando no CI. Contribuidores devem rodar `@kairos *pre-push` localmente antes de abrir o PR — o workflow é a validação automática do subset determinístico dos checks. Stack-agnóstico: bash + yq + shasum + grep, zero Node.

### Decisões tomadas

- **Opção (b) script externo em vez de inline bash:** facilita teste local (`bash .github/scripts/validate-manifest.sh`) sem precisar simular o workflow GHA; permite evolução independente do YAML do workflow
- **sha256 diverge = FAIL (não WARN) em CI:** alinhado com o AC da story — CI é mais rígido que `*doctor` local, que trata drift como WARN; contribuidores devem rodar `*pre-push` local antes do PR
- **`strenv()` do yq v4 para variáveis de ambiente em queries:** evita injeção de path como string no query yq, que seria inseguro e quebraria para paths com caracteres especiais
- **`grep -cF` com `|| echo 0`:** garante que a contagem de markers nunca falha com erro de saída quando não há match (grep retorna exit code 1 quando zero matches)
