## Objetivo

Corrigir `kairos-pre-push.md` para que a mensagem de commit sugerida seja derivada das mudanças reais (git diff / git status) e nunca referencie o ID ou título de uma story diretamente.

## Contexto

O `*pre-push` sugere mensagens de commit que incluem o título da story ativa (ex: `fix: story 3.20 - README.md não atualizado no bump de versão`). Isso é problemático por dois motivos: (1) IDs de story são internos ao ambiente do desenvolvedor e não pertencem ao histórico git de um repositório público; (2) o título da story nem sempre descreve o que de fato mudou nos arquivos.

A abordagem correta — derivar a descrição do git, sem prompt ao usuário — já foi aplicada para entradas do CHANGELOG (story 3.18). A mensagem de commit deve seguir o mesmo princípio.

## Critérios de Aceite

- [ ] AC1: A mensagem de commit sugerida pelo `*pre-push` é derivada dos arquivos modificados / diff (mesmo padrão já usado para o CHANGELOG após story 3.18) — sem interpolação de `{story_id}`, `{story_title}` ou qualquer campo da story ativa
- [ ] AC2: O formato da mensagem segue conventional commits: `{type}: {descrição semântica dos changes} v{versão}` — onde `{type}` é inferido do conteúdo (fix, feat, chore, docs etc.)
- [ ] AC3: Localizar e remover todos os templates/instruções em `kairos-pre-push.md` que referenciam story ID ou story title na construção da mensagem de commit
- [ ] AC4: Se uma story ativa existe, ela pode ser mencionada apenas em comentário interno (ex: no corpo estendido do commit, não no subject), nunca no subject line

## Fora de Escopo

- Mudanças no formato das entradas do CHANGELOG (já tratado na story 3.18/3.19)
- Mudanças em `kairos-version-bump.md` (apenas o pre-push usa mensagem de commit)
