## Objetivo

Resolver o problema do SHA auto-referencial do `manifest.yaml`: como o arquivo contém seu próprio SHA, qualquer escrita no campo `sha256` muda o conteúdo do arquivo, tornando o SHA imediatamente obsoleto. A solução é substituir o SHA real por um sentinel `self-referential` e fazer o Passo 2.6 do `*pre-push` ignorar essa entrada.

## Contexto

Story 5.6 adicionou `manifest.yaml` a `owned_files` para que ele fosse incluído no push-dual (Passo 2a) e chegasse ao `origin/main`. Efeito colateral: o Passo 2.6 do `*pre-push` passou a tentar sincronizar o SHA do manifest, mas como o SHA está dentro do próprio arquivo, cada escrita cria um novo hash, gerando um loop infinito de drift. Identificado durante o push de 2026-04-19.

## Critérios de Aceite

- [x] A entrada do `manifest.yaml` em `owned_files` tem `sha256: self-referential` (valor de string fixo)
- [x] O Passo 2.6 do `kairos-pre-push.md` detecta `sha256: self-referential` e pula o cálculo para essa entrada (sem tentar atualizar)
- [x] O `*doctor` (kairos-doctor.md) reconhece `self-referential` como valor válido — não reporta como drift
- [x] Após a fix, rodar `*pre-push` não gera mudanças no `manifest.yaml` (SHA sync é no-op para manifest.yaml)
- [x] A lógica de skip não afeta outros arquivos — apenas entradas com `sha256: self-referential`

## Fora de Escopo

- Outros arquivos que possam ter problema similar (não existem no estado atual)
- Mudança na estrutura do manifesto além do campo sha256 da entrada do manifest.yaml
- Mecanismo de SHA normalizado (hash com campo zerado) — sentinel é suficiente para o caso
