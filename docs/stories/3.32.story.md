## Objetivo

Redefinir o YOLO mode (em `kairos.md` seção `yolo_mode`) como **autonomia de execução ponta-a-ponta até a implementação**, desacoplado do pipeline de release Git. O YOLO atual encadeia `*review` → `*pre-push` após cada comando, acoplando execução ao Git. Após a Story 3.31 — onde `*version`, `*pre-push` e `*push` se tornam Git-dependentes — esse acoplamento se torna incoerente. O novo YOLO deve: receber a intenção do usuário, derivar tudo automaticamente (story/squad + implementação), parar com um relatório, perguntar se quer marcar como Done, e deixar o pipeline de release (`*push`) para decisão manual do usuário.

## Contexto

### Cadeia YOLO atual (pré-3.31)

```
*yolo on → comando → executa sem elicitação → *review → *pre-push → ⛔ (push manual)
```

Problemas:
- Acopla execução ao Git (`*pre-push` usa Git, `*review` gera gate)
- Encadeia review/pre-push após cada comando individualmente
- Não encadeia `*implement` automaticamente — o usuário precisa rodar separado

### Cadeia YOLO ideal pós-3.31

```
*yolo on
  ↓
*new-story "quero X"
  → @kairos identifica intenção, pula elicitação, gera story
  → encadeia *implement automaticamente
  → ✅ relatório do que foi feito
  → pergunta: "marcar como Done?" (s/n)
  → para (sem commit, sem push)

*new-squad "quero Y"
  → @kairos identifica intenção, pula elicitação, scaffolda squad completo
  → encadeia *implement (da story auto-criada pelo *new-squad)
  → ✅ relatório do que foi feito
  → pergunta: "marcar como Done?" (s/n)
  → para (sem commit, sem push)

*implement {id}
  → executa sem confirmações
  → ✅ relatório do que foi feito
  → pergunta: "marcar como Done?" (s/n)
  → para (sem commit, sem push)
```

**Princípio:** o YOLO cuida de **criar e implementar**. O pipeline de release (`*version` → `*pre-push` → `*push`) é decisão separada do usuário.

**Nota sobre Done:** Em YOLO, o prompt de Done é direto (sem sugestão de `*review`). Para o fluxo interativo com Done em `*implement` e `*review`, ver Story 3.33.

## Critérios de Aceite

### Encadeamento automático até implementação

- [x] `kairos.md` seção `autonomous_behavior` reescrita com encadeamento: quando um comando YOLO gera uma story `type: instance` (ex: `*new-story`, `*new-squad`), `@kairos` encadeia `*implement` automaticamente na sequência — sem pedir confirmação
- [x] `*new-story` em YOLO: recebe descrição livre → identifica intenção → gera story sem elicitação → encadeia `*implement` → relatório → prompt Done
- [x] `*new-squad` em YOLO: recebe descrição livre → identifica intenção → scaffolda squad (Modo Propósito, sem confirmação) → encadeia `*implement` da story auto-criada → relatório → prompt Done
- [x] `*implement` em YOLO: executa sem confirmações intermediárias → relatório → prompt Done (sem sugestão de `*review`)
- [x] `*update-squad` em YOLO: recebe descrição livre → identifica intenção → cria story `type: instance` sem elicitação → encadeia `*implement` da story criada → relatório → prompt Done
- [x] `*workers` em YOLO: executa sem elicitação/confirmações → se auto-criar story (worker requer script/persona nova): encadeia `*implement` → relatório → prompt Done. Se apenas listar workers: relatório simples (sem prompt Done)

### Remoção do pipeline de release do YOLO

- [x] `kairos.md` seção `autonomous_behavior` itens 4-7 removidos: sem encadeamento de `*review`, `*pre-push` ou `*push`
- [x] Tratamento de BLOCK removido — sem `*review` no YOLO, não há gate, não há retry

### Prompt de Done em YOLO

- [x] Após concluir `*implement` (direto ou encadeado), exibir prompt: "Marcar story {id} como Done? (s/n)"
- [x] Se `s`: transicionar status para Done + atualizar change log da story + atualizar status no epic (lógica compartilhada com Story 3.33)
- [x] Se `n`: story permanece `In Review` (status já transicionado pelo `*implement`), relatório avisa "Story permanece em aberto"
- [x] O prompt de Done em YOLO **não sugere `*review`** — é decisão direta (o YOLO pula review por design)

### Aviso e relatório

- [x] `kairos.md` seção `commands` → `*yolo on` → texto do aviso reescrito:
  - "O que muda": "Elicitação e confirmações suprimidas. Ao criar story ou squad, `*implement` é encadeado automaticamente. Ao concluir: exibe relatório e pergunta se quer marcar Done."
  - "O que NÃO muda": "Pipeline de release (`*version`, `*pre-push`, `*push`) permanece separado — rode manualmente quando quiser commitar e empurrar."
- [x] Ao concluir um comando YOLO, `@kairos` exibe relatório formatado:
  ```
  ⚡ YOLO: {comando} concluído.

  {resumo — arquivos criados/modificados, story gerada/implementada, squad scaffoldado}

  Marcar story {id} como Done? (s/n)
  ⚠️ Nenhum commit foi feito. Rode *push quando quiser commitar e empurrar.
  ```
