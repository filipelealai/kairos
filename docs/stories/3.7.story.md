# Story 3.7 — scope.md do Framework em .kairos-core/docs/ e *architecture {squad}

**Epic:** 3 — Governança e Versionamento
**Status:** Draft
**Complexidade:** M
**Tipo:** kairos-core
**Criada por:** @kairos
**Data:** 2026-04-15

---

## Objetivo

Corrigir a contradição entre a `kairos-prd.md` ("O PRD do Kairos vive em `docs/scope.md`") e o manifest ("docs/scope.md é metadado de instância"): criar `.kairos-core/docs/scope.md` como o documento de escopo do framework (kairos-owned, L3), manter `docs/scope.md` como escopo da instância gerenciado por `*prd`, e expandir `*architecture` para aceitar `{squad}` e gerenciar data-flow docs tanto a nível de framework quanto de squad.

---

## Critérios de Aceite

### Novo arquivo de escopo do framework

- [ ] `.kairos-core/docs/scope.md` criado — documento de escopo e arquitetura do Kairos **como framework** (genérico, sem referências a squads específicos desta instância); inclui frontmatter `kairos-owned: true`; estrutura: visão geral, propósito, arquitetura de agentes, modelo de governance, stack de referência
- [ ] `.kairos-core/docs/scope.md` adicionado ao `manifest.yaml` como L3
- [ ] `docs/scope.md` permanece como escopo **da instância** (user-owned, não entra no manifest — já classificado como metadado de instância nas notas do manifest)

### *prd: clarificado como gestão do escopo da instância

- [ ] `kairos-prd.md` atualizado — remover "O PRD do Kairos vive em `docs/scope.md`"; substituir por "docs/scope.md é o escopo desta instância do Kairos — descreve os squads, objetivos e restrições específicos deste projeto"
- [ ] Elicitação do `*prd` (Pergunta 1) atualizada: "Para quem esta **instância** do Kairos serve e qual é o foco dela?" (não "o que é o Kairos" — isso é framework)
- [ ] Formato de `docs/scope.md` atualizado: título do arquivo passa de "Kairos — Escopo e Objetivos" para "Instância Kairos — Escopo e Objetivos da Instância"
- [ ] `core-config.yaml` (chave `framework.scopeFile`) atualizada: `scopeFile: docs/scope.md` → `frameworkScopeFile: .kairos-core/docs/scope.md`; nova chave `instanceScopeFile: docs/scope.md` adicionada

### *architecture: leitura dinâmica e modo squad

- [ ] `kairos-architecture.md` — Passo 1 (Stack): substituir leitura de `docs/scope.md` por leitura de `.kairos-core/docs/scope.md` para a stack declarada do framework; `docs/scope.md` (instância) referenciado separadamente como "escopo da instância"
- [ ] `kairos-architecture.md` — Passo 4 (Data Flow): remover referências hardcoded a `campaign-analyst.ts` e outros scripts de squad; substituir por leitura dinâmica de `core-config.yaml → agents.squads` para descobrir os agentes ativos e seus scripts em `src/agents/`
- [ ] `kairos-architecture.md` — novo modo `*architecture {squad}`:
  - Recebe o nome de um squad como argumento
  - Verifica se `squads/{squad}/` existe; se não, HALT com lista de squads disponíveis
  - Cria ou atualiza `squads/{squad}/workflows/data-flow.md` descrevendo o fluxo de dados do squad: inputs, etapas do pipeline, outputs, integrações externas
  - Valida consistência: agentes declarados em `squad.yaml` têm scripts e estão documentados no data-flow?
  - Resultado: CONSISTENTE / DRIFT / INCOMPLETO
- [ ] `kairos-architecture.md` — sem argumento (comportamento atual): mantém auditoria geral do framework, agora lendo dinamicamente os agentes de `core-config.yaml` em vez de hardcodar

### Persona e Help

- [ ] `kairos-help.md` — assinatura de `*architecture` atualizada para `*architecture [{squad}]`; descrição expandida para mencionar o modo squad
- [ ] Persona `kairos.md` — descrição do comando `*architecture` atualizada: `*architecture [{squad}]`

## Fora de Escopo

- Migrar o conteúdo existente de `docs/scope.md` para `.kairos-core/docs/scope.md` (o conteúdo atual de `docs/scope.md` é da instância — fica onde está)
- Implementar `*architecture all-squads` para rodar o modo squad em todos os squads de uma vez
- Criar `squads/{squad}/workflows/` se não existir (pré-condição esperada do scaffold de *new-squad)
