## Objetivo

Corrigir o fallback de epoch para gate não commitado no step 4 do Passo 2 de `kairos-pre-push.md`: o valor `0` causa falso skip porque `epoch_changelog > 0 = epoch_gate` satisfaz a condição de skip. O fallback correto é um sentinel alto (`99999999999`) que garante `epoch_changelog > epoch_gate` sempre falso quando o gate ainda não foi commitado.

## Contexto do Bug

Story 3.14 implementou comparação por timestamp epoch unix para substituir comparação por data-dia. O fallback `0` para gate não commitado foi documentado como "força exibição do prompt", mas a lógica é invertida: skip ocorre quando `epoch_changelog > epoch_gate`. Com `epoch_gate = 0` e qualquer `epoch_changelog > 0` (CHANGELOG sempre tem commit), a condição de skip é satisfeita e o prompt é suprimido — o oposto do comportamento desejado.

## Critérios de Aceite

- [x] Fallback de `epoch_gate` quando `git log` retorna vazio alterado de `0` para `99999999999` em `kairos-pre-push.md`
- [x] Comentário inline na instrução confirma: sentinel alto garante que `epoch_changelog > epoch_gate` seja falso (prompt sempre aparece quando gate não commitado)
- [x] Fallback de `epoch_changelog` permanece `0` — se CHANGELOG não tem commit, `0 <= epoch_gate` → prompt aparece (comportamento correto)
- [x] Nota explicativa no step 4 atualizada para refletir a lógica corrigida dos dois fallbacks

## Fora de Escopo

- Alterar a condição de skip em si (`epoch_changelog > epoch_gate`)
- Modificar o comportamento para gates já commitados
- Alterar lógica de MINOR/MAJOR (steps 1–3)

### Decisões tomadas

- **Sentinel `99999999999` para epoch_gate:** valor suficientemente alto para que nenhum timestamp real jamais supere (equivale a ~2286, seguro por décadas). Não usamos `MAX_INT` ou `Infinity` pois a instrução é texto — qualquer número alto legível funciona.
- **Sem alteração no fallback de `epoch_changelog`:** permanece `0` porque a lógica já está correta: CHANGELOG sem commit → `0 <= epoch_gate` → prompt aparece.
