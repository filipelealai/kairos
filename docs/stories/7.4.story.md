## Objetivo

Permitir que outputs do Kairos sejam automaticamente sincronizados para uma pasta de nuvem compartilhada com o time, sem implementar OAuth no framework. A solução delega o sync ao app oficial do provedor (Google Drive Desktop, OneDrive, Dropbox): o Kairos só cria um symlink de `data/outputs/` para a pasta sincronizada local. Zero auth, multi-provedor, multi-SO.

---

## Critérios de Aceite

- [ ] Nova task `.kairos-core/tasks/kairos-configure-cloud.md` com fluxo:
  1. Pergunta amigavelmente se o usuário tem app de sync instalado (Drive Desktop, OneDrive, Dropbox, iCloud) — explica brevemente o que fazer se não tem
  2. Pede o caminho local da pasta sincronizada compartilhada com o time
  3. Valida que o caminho existe e é gravável
  4. Se `data/outputs/` já existe e tem conteúdo: pergunta se deseja mover o conteúdo existente para a pasta destino antes de criar o symlink
  5. Cria o symlink `data/outputs/ → {caminho informado}`
  6. Valida o symlink rodando uma escrita-leitura de teste
  7. Reporta sucesso na sessão; salva config em `.kairos-core/runtime/cloud-sync.json` (caminho atual + provedor declarado)
- [ ] Comando `*configure-cloud` adicionado à persona `@kairos`
- [ ] Subcomando `*configure-cloud --reset` desfaz o symlink e restaura `data/outputs/` como pasta local normal (preserva conteúdo)
- [ ] Em Windows, se a criação de symlink falhar por falta de privilégio: mensagem clara explicando que precisa de Developer Mode habilitado ou shell admin, com instruções diretas. Sem fallback automático para variável de path (decisão arquitetural)
- [ ] `kairos-doctor.md` ganha check: se `cloud-sync.json` existe, valida que o symlink ainda aponta para caminho gravável; warning se quebrado
- [ ] Manifesto registra a nova task como `owned_files`
- [ ] Smoke test: configurar para uma pasta `~/test-drive/Kairos/`; rodar agente que gera output; verificar que arquivo aparece em `~/test-drive/Kairos/`; rodar `*configure-cloud --reset` e verificar volta ao normal

---

## Fora de Escopo

- Implementação de OAuth Drive nativa no framework (decisão arquitetural — fica delegado ao app do provedor)
- Sync seletivo (apenas alguns squads/agentes) — symlink é de `data/outputs/` inteiro
- Sync bidirecional inteligente com resolução de conflitos — quem resolve conflito é o app de sync do provedor
- Integração no `install.sh`/`.ps1` — fica para a Story 7.6 (que chama `*configure-cloud` se opt-in)
