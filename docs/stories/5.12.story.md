## Objetivo

Introduzir a categoria `sync_files` no manifest — arquivos que são sincronizados integralmente para `origin/main` (documentação pública do GitHub), mas não são framework-owned no sentido de update: o usuário os customiza livremente e um `kairos update` futuro nunca os sobrescreve. Mover `README.md` de `owned_files` para `sync_files`.

## Contexto

`README.md` hoje vive em `owned_files` como L3, o que cria uma contradição: ele tem SHA de update e seria sobrescrito por um `kairos update` futuro, mas seu conteúdo é instância-específico (nome do projeto, squads ativos, owner). Ao mesmo tempo, precisa ir para `origin/main` pois é a documentação pública do repositório GitHub.

A separação de concerns é clara:
- `owned_files` → framework puro, gerenciado por updates
- `sync_files` → conteúdo da instância com valor público, sincronizado mas nunca sobrescrito por update
- `owned_sections` → arquivos mistos (framework + usuário)

## Critérios de Aceite

- [x] `manifest.yaml` tem nova categoria top-level `sync_files` com campos `path` e `layer` por entrada
- [x] `README.md` é removido de `owned_files` e adicionado a `sync_files` (sem campo `sha256`)
- [x] `push-dual` Passo 2a inclui entradas de `sync_files` no mesmo `git checkout filipe-instance -- {path}`, com nota explicando a diferença semântica (sync sem ownership)
- [x] `*doctor` Check 9 valida existência de arquivos em `sync_files` (→ ❌ FAIL se ausente); não valida SHA (sem sha256 nessa categoria)
- [x] `ownership.md` ou `kairos-kb.md` documenta o conceito de `sync_files`: "sincronizado para main, nunca sobrescrito por update"
- [x] Manifest guard (`*pre-push` Passo 0) não é afetado — `sync_files` não exige `kairos-owned: true` (README.md não tem frontmatter YAML)

## Fora de Escopo

- Adicionar outros arquivos a `sync_files` além de `README.md` (a categoria é criada para o caso geral, mas só README.md entra agora)
- SHA tracking para `sync_files` (a ausência de SHA é intencional — não há "drift" a detectar)
- Implementação do updater (`kairos update`) — apenas o contrato do manifest é estabelecido aqui
- Mudanças no CHANGELOG.md (permanece em `owned_files` — é framework-owned de fato)
