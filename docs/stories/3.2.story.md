## Objetivo

Tornar o `*pre-push` o centro do pré-voo: ele trata tudo que precisa acontecer antes do push — verificação do gate de review, bump de versão interativo (para stories MINOR/MAJOR sem bump), e commit com a versão já incluída. O `*review` permanece focado exclusivamente em validar implementações. O commit deixa de ser um passo manual invisível entre os dois comandos.

---

## Critérios de Aceite

- [x] `kairos-pre-push.md` atualizada — Passo 1 (gate de review): para stories MINOR/MAJOR, verifica se existe gate PASS ou RESSALVA em `docs/qa/gates/`; se não existir → BLOCK com instrução para rodar `*review` antes
- [x] `kairos-pre-push.md` — Passo 2 (versionamento): detecta stories MINOR/MAJOR com gate PASS/RESSALVA mas sem bump de versão correspondente no `CHANGELOG.md`; se detectado, pergunta "Story {id} é {MINOR/MAJOR} — sem bump. Qual tipo? (patch/minor/major)" e executa o bump chamando a lógica de `kairos-version-bump.md` inline
- [x] `kairos-pre-push.md` — Passo 3 (commit): após versão confirmada, verifica uncommitted changes relevantes (excluindo `.kairos-core/runtime/`, `data/`, `node_modules/`); se houver, sugere mensagem de commit e pergunta "Deseja fazer commit agora? (s/n)"; se sim, executa git add + git commit; se não, BLOCK com instrução
- [x] A mensagem de commit sugerida incorpora versão e story: `feat: {story-title-em-kebab-case} (story {id}) v{version}`
- [x] `kairos-pre-push.md` — Passo 4 (referências): spot check de referências quebradas (arquivos `.md` modificados — links e referências a tasks)
- [x] `kairos-pre-push.md` — Passo 5 (consistência final): verifica que `core-config.yaml` e `CHANGELOG.md` têm a mesma versão como entrada mais recente
- [x] `*review` NÃO é modificado — permanece focado em validação de implementação (ACs, arquivos, Execution Log, gate)
- [x] `kairos-help.md` e persona `kairos.md` atualizados — fluxo ③ reflete que `*pre-push` trata versão + commit; `*version` permanece como comando direto para uso avulso

### Decisões tomadas

- **Bump inline vs. chamar kairos-version-bump.md:** implementada inline para não exigir carregamento de outra task no meio do fluxo. O comportamento é idêntico — nenhuma duplicação de lógica a longo prazo; se kairos-version-bump.md mudar, o pre-push precisará ser atualizado junto. Trade-off aceito: coesão de fluxo > DRY neste caso.
- **Detecção de "bump pendente":** usa comparação de datas entre o arquivo de gate (`{story-id}-YYYY-MM-DD.yaml`) e a entrada mais recente do CHANGELOG.md. Abordagem pragmática sem acesso a git timestamps.
- **Pré-check de git status:** mantido como passo implícito antes dos 5 passos formais, para que todas as informações (branch, último commit, arquivos modificados) estejam disponíveis durante a execução.
