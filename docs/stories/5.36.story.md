# Story 5.36 — *regenerate-squad: preservar blocos kairos-custom durante regeneração

**Epic:** 5
**Status:** Done
**Complexidade:** M
**Tipo:** kairos-core
**Criada por:** @kairos
**Data:** 2026-04-29

---

## Objetivo

Atualmente, quando `*regenerate-squad` regenera uma persona a partir do YAML de origem (por SHA drift), ele sobrescreve o arquivo inteiro — incluindo quaisquer blocos `<!-- kairos-custom-start --> ... <!-- kairos-custom-end -->` adicionados pós-geração. Esses blocos são customizações de instância (ex: protocolos de uso de templates, aviso de rascunho, integração com tasks externas) e devem ser tratados como seções user-owned dentro de um arquivo framework-managed.

Esta story faz `*regenerate-squad` preservar blocos kairos-custom durante regenerações, evitando perda silenciosa de customizações de instância.

## Contexto

Identificado no review da story 4.4: o bloco `<!-- kairos-custom-start -->` da persona `contract-writer.md` (adicionado em 4.3) não está no YAML de origem. Se o YAML for modificado, *regenerate-squad detectaria drift, regeneraria da fonte e perderia o bloco. O mesmo ocorre com `brief-extractor.md`.

O padrão é recorrente: arquivos framework-managed com seções user-owned pós-geração não têm proteção de preservação no ciclo de regeneração.

## Critérios de Aceite

- [x] `kairos-regenerate-squad.md` atualizado com protocolo de preservação: antes de regenerar, extrair blocos `<!-- kairos-custom-start --> ... <!-- kairos-custom-end -->` existentes na persona atual; após regenerar do YAML, re-injetar os blocos extraídos na mesma posição relativa (ou, se a posição não for identificável, antes da linha de fechamento `*Kairos Agent — ...`)
- [x] Se a persona não tem blocos kairos-custom, o comportamento de regeneração permanece inalterado
- [x] Se a persona tem um ou mais blocos kairos-custom, o log de regeneração exibe: `→ {N} bloco(s) kairos-custom preservado(s)` por persona regenerada
- [x] Task documenta explicitamente o contrato: "blocos kairos-custom são seções user-owned dentro de personas framework-managed — nunca sobrescrever durante regeneração"
- [x] Verificação retroativa: após o fix, confirmar que `contract-writer.md` e `brief-extractor.md` (as duas personas com kairos-custom conhecidas) não seriam afetadas por uma regeneração (SHAs atuais batem — não há drift ativo; o fix protege regenerações futuras)

## Fora de Escopo

- Mudança no formato do YAML de origem para incluir conteúdo kairos-custom
- Modificação dos blocos kairos-custom existentes em `contract-writer.md` ou `brief-extractor.md` (coberto por story 4.5)
- Suporte a outros tipos de blocos customizados além de `kairos-custom-start/end`

### O que foi feito

- `kairos-regenerate-squad.md` já tinha Passo 2.1 com preservação de kairos-custom desde v3.11.0 (commit fb257da). A story identificou três lacunas remanescentes e todas foram corrigidas:
  1. Passo 2.1 atualizado para extrair **todos** os blocos (não apenas um), contar N e guardar como lista ordenada `custom_blocks_{id}`
  2. Passo 3 (Sumário) atualizado para exibir `→ {N} bloco(s) kairos-custom preservado(s)` por persona regenerada (apenas se N > 0)
  3. Notas de Implementação expandidas com: contrato explícito ("user-owned dentro de personas framework-managed — nunca sobrescrever"), suporte a múltiplos blocos, e clareza de que comportamento inalterado quando N=0
- Adicionado label `**Contrato:**` diretamente no Passo 2.1 para visibilidade imediata ao executor
- Verificação retroativa executada: SHAs de `contract-writer.md` e `brief-extractor.md` coincidem com seus YAMLs de origem — sem drift ativo; fix protege regenerações futuras

### Decisões tomadas

- **Contrato em Passo 2.1, não como seção separada:** colocar o label `**Contrato:**` diretamente onde o executor toma a decisão de preservar (Passo 2.1) é mais efetivo do que uma seção isolada — garante que seja lido no momento de ação
- **`custom_blocks_{id}` como lista, não string única:** alteração de `custom_block_{id}` (singular) para `custom_blocks_{id}` (lista) permite contar N e preservar ordem de múltiplos blocos sem ambiguidade. Retrocompatível com caso N=1 (lista de um item)
- **Log condicional `(exibir apenas se N > 0)`:** não exibir o log quando não há blocos evita ruído e satisfaz o AC "comportamento inalterado quando sem kairos-custom"
