## Objetivo

Executar a transição física para repo público: separar `main` (framework puro, `filipelealweb/kairos` público) de `filipe-instance` (branch privada em `filipelealweb/kairos-pessoal`), e criar o squad `ops` com a task `push-dual` que mantém os dois remotes sincronizados com um único comando.

## Contexto

A separação lógica foi concluída na story 5.1 (manifesto, default-deny, relocações). Esta story executa a separação física e cria a infraestrutura de instância para gerenciar o fluxo dual de push.

**Arquitetura completa (local + remotes):**
```
LOCAL — um único repo git, dois branches, dois remotes

  branch filipe-instance  ←── você trabalha aqui (tudo: framework + instância)
         │                       ↓ push-dual
         │                git push private filipe-instance
         │                       ↓
         │                filipelealweb/kairos-pessoal  (GitHub privado)
         │
         └─ sync automático via push-dual (git checkout filipe-instance -- <framework files>)
                ↓
  branch main             ←── nunca tocada diretamente; gerenciada pelo push-dual
                                ↓ push-dual
                          git push origin main
                                ↓
                          filipelealweb/kairos  (GitHub público — só framework)
```

**Remotes:**
```
origin  → filipelealweb/kairos         (público — framework puro)
private → filipelealweb/kairos-pessoal  (privado — conteúdo completo)
```

**Contrato framework/instância:**
- `push-dual.md` vive em `squads/ops/tasks/` — user-owned por design de squad
- `kairos-push.md` (framework L2) permanece inalterado
- O squad `ops` é o namespace canônico para tasks operacionais desta instância

**Squad `ops` — é task-based, sem agent persona obrigatória.** O executor decide se cria um `@ops` agent ou deixa o squad apenas com tasks executadas diretamente pelo @kairos. Dado que `push-dual` é uma operação de governança de repo, faz sentido ser executada pelo @kairos sem persona intermediária.

**`push-dual.md` — mecanismo de sync:**
A task lê `manifest.yaml` para obter a lista de `owned_files`, usa `git checkout filipe-instance -- {path}` para cada arquivo, garantindo que `main` recebe exatamente e somente os arquivos framework — sem depender de `.gitignore` para a separação.

### Decisões tomadas

- **`git add -f` para .gitkeep dentro de diretórios ignorados:** git não permite `!dir/.gitkeep` quando o padrão é `dir/` (diretório). Solução: force-add. Arquivos uma vez commitados ficam tracked independente do `.gitignore`. Alternativa descartada: mudar para `dir/**` (mais complexo, comportamento de glob diferente).
- **Squad sem persona:** `push-dual` é operação de governança de repo, faz mais sentido como task do @kairos sem intermediário. Decisão alinhada com as notas da story.
- **Lista hardcoded em push-dual.md:** a lista de `git checkout` espelha o `manifest.yaml` na data da story. Story 5.3 atualizará os SHAs; a manutenção da lista em push-dual é responsabilidade do usuário ao evoluir o manifesto.
- **CLAUDE.md mixed file:** push-dual não sincroniza CLAUDE.md para `main` (arquivo misto). A seção user-owned com `ops` fica apenas em `filipe-instance`. Essa é a arquitetura correta — `main` não carrega conteúdo de instância.
