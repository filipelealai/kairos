# Story 3.4 — *review-squad: Validação de Coerência de Squad

**Epic:** 3 — Governança e Versionamento
**Status:** Done
**Complexidade:** M
**Criada por:** @kairos
**Data:** 2026-04-15

---

## Objetivo

Criar o comando `*review-squad {squad}` para validar se a configuração de um squad instanciado é coerente e completa: personas declaradas existem, tasks referenciadas existem, squad.yaml tem campos obrigatórios e o pipeline está documentado. Distinto do `*doctor` (que diagnostica o framework) — `*review-squad` é para conteúdo instanciado pelo usuário.

---

## Critérios de Aceite

- [x] Nova task `kairos-review-squad.md` criada em `.kairos-core/tasks/`
- [x] A task recebe `{squad}` como argumento obrigatório; se omitido, lista os squads disponíveis (lidos de `core-config.yaml`) e pede ao usuário que escolha
- [x] Check 1 — `squad.yaml` válido: arquivo existe em `squads/{squad}/squad.yaml`; campos obrigatórios presentes: `name`, `agents` (lista), `status`
- [x] Check 2 — Personas existem: para cada agente listado em `squad.yaml → agents`, verifica se existe arquivo de persona em `.claude/commands/kairos/agents/{agent-id}.md`
- [x] Check 3 — Tasks existem: para cada task referenciada nas personas e no `squad.yaml` (campo `tasks` se presente), verifica se existe em `.kairos-core/tasks/{task}.md`
- [x] Check 4 — Pipeline documentado: verifica se existe pelo menos um arquivo em `squads/{squad}/rules/` (regras do squad) e um em `squads/{squad}/` descrevendo o pipeline (qualquer `.md` ou `squad.yaml` com campo `pipeline`)
- [x] Check 5 — Agents MEMORY.md: para cada agente do squad, verifica se existe `.kairos-core/agents/{agent-id}/MEMORY.md`
- [x] O resultado é exibido como `VÁLIDO` / `INCOMPLETO` / `QUEBRADO` (não PASS/BLOCK — não é gate de story, é diagnóstico de squad instanciado)
- [x] Persona `kairos.md` atualizada — comando `*review-squad {squad}` adicionado na seção de comandos, com `visibility: [full, quick]`
- [x] `kairos-help.md` atualizado — `*review-squad` na Seção 2 (comandos), Seção 4 (quando não usar @kairos menciona que *review-squad é o caminho para squads instanciados), cheat sheet atualizado

### Decisões tomadas

- **Flexibilidade de formato no Check 1:** `squad.yaml` real do cold-prospecting usa `components.agents` (paths) e não tem `status` — a task aceita ambas as formas (top-level `agents` OU `components.agents`) e busca `status` também no `core-config.yaml`, evitando falso QUEBRADO para squads válidos já instanciados.
- **Check 3 — tasks de squad vs framework:** tasks de squad (`squads/{squad}/tasks/`) são WARN se ausentes (podem ser stubs a criar); tasks de framework referenciadas nas personas são FAIL se ausentes (são dependências operacionais críticas).
- **`*doctor` adicionado ao help:** aproveitei a seção DIAGNÓSTICO nova para documentar `*doctor` também, já que ele não aparecia explicitamente na Seção 2 do help original.
