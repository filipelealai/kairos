⚠️  ATENÇÃO — MODIFICAÇÃO DO NÚCLEO DO KAIROS
────────────────────────────────────────────────────────────
Esta story modifica o núcleo do framework Kairos. Alterações
são livres (Kairos é open-source), mas podem impedir futuras
atualizações automáticas, e podem ser sobrescritas por
eventuais atualizações. Ao prosseguir, você estará fazendo
um fork local do Kairos. Continue com consciência — por conta
e risco do usuário.
────────────────────────────────────────────────────────────

## Objetivo

Corrigir o `README.md` para refletir com precisão a arquitetura atual: framework stack-agnóstico (markdown + YAML + CJS), `src/` como conteúdo user-owned, e `ANTHROPIC_API_KEY` como opcional condicionado ao uso de scripts/squads com chamadas diretas à API — removendo hardcodes e falsos positivos que fazem o README público mentir sobre o que o Kairos é.

> **Bump:** PATCH — correção documental em `sync_files`.

## Critérios de Aceite

- [x] Versão no README corrigida de `3.5.1` para `3.6.0`
- [x] Seção "Stack" reescrita distinguindo duas camadas: (a) **Framework** — markdown, YAML, CJS hooks — sem dependência de runtime de linguagem; (b) **Instância** — stack que o usuário utiliza, o Kairos apenas interage e governa, não depende de uma stack
- [x] Seção "Pré-requisitos" alterada para refletir a compatibilidade multi-stack do Kairos; stack, dependências e chaves no .env são responsabilidade e preferência do usuário (quando instância utiliza)
- [x] Seção "Pipeline de squad (exemplo)" e tabela de personas: agentes específicos da instância (`@campaign-analyst` Clio, `@lead-scorer` Lex, `@niche-classifier` Nix, `@email-writer` Eva) substituídos por placeholders genéricos (`@{agente}`, `*{comando}`) ou por descrição textual — sem dados de instância no README público; exemplos genéricos fidedignos com nome e função de placeholder podem complementar
- [x] Seção "Como rodar um agente": substituir conteúdo TypeScript específico por sintaxe correta do Kairos para usar agentes (`@nome-do-agente *comando`); conteúdo de `data/outputs/{squad}/` exemplificado como `reports/` e `emails/` aparece explicitamente como exemplo (instanciado)
- [x] Referência a `src/tools/claude.ts` removida na seção "Estrutura"
- [x] Seção "Estrutura do repositório": em `src/` manter apenas `src/agents/` comentado como user-owned, onde residem scripts e ferramentas utilizados por agentes e squads (quando é o caso); atualizar estrutura de `.kairos-core/` e `.claude/` (exceto conteúdo user-owned); criar `.github/` (apenas resumo do conteúdo, sem listar arquivos e pastas)
- [x] README resultante é apropriado para o repo público `filipelealweb/kairos` — sem dados pessoais, sem conteúdo de instância específica, sem afirmações falsas sobre o framework
