## Objetivo

Substituir a mensagem hardcoded do commit do Passo 3 do `push-dual` pela mensagem do commit correspondente em `filipe-instance`, eliminando a exposição do nome da branch privada no histórico público do `main`.

## Contexto

Hoje o Passo 3 comita com:

```
sync: framework files from filipe-instance → main (push-dual)
```

Isso é problemático: expõe o nome da branch privada no repo público e perde o contexto real do que foi feito. O histórico do `main` deve refletir o que mudou no framework — a mesma mensagem que já descreve o trabalho no `filipe-instance`.

## Critérios de Aceite

- [x] AC1: O commit do Passo 3 usa a mensagem do commit mais recente de `filipe-instance` em vez da string hardcoded — obtida via `git log filipe-instance -1 --pretty=%B` antes do `git checkout main`
- [x] AC2: Nenhuma referência ao nome da branch privada (`filipe-instance` ou similar) aparece na mensagem de commit que vai para `main`
- [x] AC3: Se `git status` estiver limpo em `main` (nenhum arquivo framework mudou), o comportamento de skip do commit permanece inalterado — sem regressão
- [x] AC4: A mensagem capturada usa `--pretty=%B` (mensagem completa, não apenas subject line)

## Fora de Escopo

- Mudar qualquer outro passo do push-dual
- Generalizar para outras branches além de `filipe-instance`
- Formatar ou prefixar a mensagem capturada

### O que foi feito

- Adicionada linha `COMMIT_MSG=$(git log filipe-instance -1 --pretty=%B)` no início do Passo 3, antes do `git status`
- `git commit -m "..."` substituído por `git commit -m "$COMMIT_MSG"`
- Removida a string hardcoded `"sync: framework files from filipe-instance → main (push-dual)"`

### Decisões tomadas

- A captura ocorre **dentro** do Passo 3 (já em `main`), não antes do `git checkout main`: `filipe-instance` ainda existe como branch local e é referenciável diretamente via `git log filipe-instance` — não há necessidade de capturar antes da troca de branch
- `--pretty=%B` preserva a mensagem completa (subject + body se houver), alinhado com AC4
