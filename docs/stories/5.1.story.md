### Decisões tomadas

- **Manifesto sobre frontmatter:** a autoridade é o manifesto, `kairos-owned: true` é apenas marker de visibilidade. Alternativa descartada: frontmatter autoritativo. Razão: frontmatter é por-arquivo e pode ser adicionado descuidadamente em qualquer arquivo; manifesto é lista fechada central, default-deny é aplicável. Doctor cross-checka os dois para detectar drift.
- **`agent-authority.md` split em dois arquivos (framework + squad):** alternativa era manter um só com subseções de squad. Descartada porque regra específica de squad NÃO é framework — viola default-deny do manifesto se ficasse dentro da rule framework-owned. A divisão deixa cada parte sob o ownership correto.
- **Stories/epics do dev do Kairos (`docs/stories/5.1`, `docs/epics/epic-5`) FORA do manifesto:** inicialmente tive tentação de adicioná-las (parecem "conteúdo framework"). Descartado: elas são **metadados deste repo** sobre a construção do Kairos, não são shipped em instalações. Mesma categoria de `README.md` e `CHANGELOG.md` — instância-específico apesar de "sobre o framework".
- **Gitignore + overlay vs. fork separado:** escolhido gitignore + branch privada. Alternativa de repos separados com subtree/submodule foi descartada: dobra manutenção, fragmenta histórico git, divergência inevitável. Reconsiderar apenas se framework ganhar CI/CD independente.
- **Ownership de `CHANGELOG.md`:** deliberadamente fora do manifesto. É metadado da instância (cada instância tem seu próprio CHANGELOG refletindo versões instaladas/updates aplicados). Framework ships template/seed apenas.
- **`docs/` é 100% user-owned, sem exceção:** inicialmente `docs/framework/` era a tentativa de segregar framework-docs dentro de `docs/`. Descartado após feedback: mistura user/framework no mesmo root é confusa e viola a regra simples. Movido para `.kairos-core/docs/` (namespace framework). Ganho: regra fica trivial de explicar — "tudo em `docs/` é seu".
- **`public-repo-transition.md` é instance, não framework:** documenta decisão one-time sobre ESTE repo (monorepo → repo público). Um usuário instalando Kairos greenfield nunca enfrenta essa transição. Classificado como ADR de instância e movido para `docs/` user-owned.
