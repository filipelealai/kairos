## Objetivo

Eliminar a instrução passiva de `self_reviewed` em `kairos-implement.md` e integrar a lógica diretamente em `kairos-review.md`: quando o Execution Log de uma story indicar `**Executor:** @kairos via *implement`, o gate YAML gerado pelo `*review` inclui automaticamente os campos `self_reviewed` e `self_review_note` — sem depender da memória do revisor.

---

## Contexto

A story 3.6 introduziu o campo `self_reviewed: true` como marcador de auditoria para gates de stories implementadas pelo mesmo agente que as revisa. A implementação colocou a instrução em `kairos-implement.md` como nota para o `*review` posterior — uma solução passiva que depende do revisor lembrar de incluir o campo. O gate de review da própria 3.6 identificou isso como RESSALVA. Esta story corrige a omissão de forma cirúrgica.

---

## Critérios de Aceite

- [x] `kairos-review.md` — Passo 3 (Ler Execution Log) atualizado: se o campo `**Executor:**` no Execution Log contém a string `@kairos via *implement`, registrar internamente `implemented_via_implement: true`

- [x] `kairos-review.md` — Passo 8 (template YAML do gate) atualizado: se `implemented_via_implement = true`, o gate gerado inclui os campos abaixo imediatamente após `execution_log_found`:
  ```yaml
  self_reviewed: true
  self_review_note: "Story implementada e revisada pelo mesmo agente (@kairos) — validação estrutural (ACs, arquivos), não independente."
  ```
  Se `implemented_via_implement = false` ou indeterminado: campos omitidos (não incluir `self_reviewed: false`)

- [x] `kairos-implement.md` — seção "Gate de *review para stories type: instance" removida (lógica movida para `kairos-review.md`; instrução passiva eliminada)

## Fora de Escopo

- Adicionar `self_reviewed` a fluxos que não envolvam `*implement`
- Modificar o schema YAML do gate além dos dois campos declarados acima
