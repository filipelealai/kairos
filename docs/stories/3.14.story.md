## Objetivo

O step 4 do Passo 2 de `kairos-pre-push.md` compara apenas datas-dia (`YYYY-MM-DD`) para decidir se um bump PATCH já foi feito desde o gate. Quando o bump anterior e o gate ocorrem no mesmo dia (calendário), a comparação retorna falso positivo e suprime o prompt — como aconteceu com as stories 3.8 e 3.9. Substituir a comparação por timestamp de commit Git, que distingue a ordem real dos eventos independente do dia.

## Critérios de Aceite

- [ ] Step 4 do Passo 2 em `kairos-pre-push.md` usa timestamp de commit Git (epoch unix) para comparar gate vs CHANGELOG — não mais data-dia `YYYY-MM-DD`
- [ ] Comando para obter epoch do gate: `git log -1 --format="%ct" -- docs/qa/gates/{story-id}-{date}.yaml`; se retornar vazio (gate não commitado), usar `0` como fallback (força exibição do prompt)
- [ ] Comando para obter epoch do último commit do CHANGELOG: `git log -1 --format="%ct" -- CHANGELOG.md`; se retornar vazio (CHANGELOG não commitado), usar `0` como fallback (força exibição do prompt)
- [ ] Condição de skip atualizada: se `epoch_changelog > epoch_gate` → bump realizado após gate → skip; se `epoch_changelog <= epoch_gate` → bump pendente → exibir prompt
- [ ] Nota explicativa adicionada no step 4 descrevendo por que timestamp é necessário (evitar regressão)
- [ ] Comportamento para MINOR/MAJOR (Passo 2, steps 1–3) permanece inalterado

## Fora de Escopo
