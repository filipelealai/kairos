# Story 3.10 — Pre-Push: Atualizar `kairos-version` nos Arquivos Modificados

**Epic:** 3

**Criada por:** @kairos

---

## Objetivo

O campo `kairos-version` no frontmatter dos arquivos de framework registra a versão em que o arquivo foi criado ou modificado pela última vez — não a versão atual do framework. Atualmente, `*pre-push` não atualiza esse campo nos arquivos que foram efetivamente modificados no ciclo, deixando a informação desatualizada silenciosamente.

---

## Critérios de Aceite

- [x] `kairos-pre-push.md` — Passo de commit expandido: após identificar os arquivos framework modificados no ciclo (arquivos rastreados pelo git com `M` ou `A`), atualizar o campo `kairos-version:` no frontmatter de cada um para a versão resultante do bump
- [x] A atualização de `kairos-version` ocorre **depois** do bump de versão e **antes** do commit — os arquivos entram no commit já com o campo atualizado
- [x] Apenas arquivos que têm frontmatter com campo `kairos-version:` existente são atualizados — arquivos sem o campo são ignorados (sem criação automática)
- [x] Arquivos não modificados no ciclo (sem `M`/`A` no git status) **não** têm seu `kairos-version` alterado — a semântica "versão quando tocado pela última vez" deve ser preservada
- [x] `ownership.md` ou seção equivalente documenta explicitamente a semântica de `kairos-version`: "versão do framework quando o arquivo foi criado ou modificado pela última vez"

## Fora de Escopo

- Retroativamente atualizar `kairos-version` em arquivos históricos que não foram modificados
- Criar o campo `kairos-version` em arquivos que ainda não o têm
- Modificar `kairos-version-bump.md` (sem mudança nessa task)
- Verificação de `kairos-version` no `*doctor` (o campo não deve ser checado contra a versão atual — seria um false positive por design)
