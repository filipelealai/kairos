## Objetivo

Empacotar o trabalho das stories 7.1–7.5 em uma experiência de instalação/desinstalação amigável para usuários não-técnicos. Instalador interativo cross-platform (Linux/Mac via `.sh`, Windows nativo via `.ps1`), download via tarball do GitHub (sem Git), elicitação user-friendly, opt-in para cloud sync, integração automática com `*configure-cloud`. Desinstalador respeita o manifesto: remove apenas framework-owned, preserva opcionalmente outputs e `.env`.

## Critérios de Aceite

### Instalador (`install.sh` + `install.ps1`)

- [x] Banner ASCII de boas-vindas + texto humano explicando o que vai acontecer
- [x] Detecta SO automaticamente (Linux/WSL/Mac em `.sh`; Windows em `.ps1`)
- [x] Em Windows com WSL2 detectado: oferece "✓ WSL2 detectado — recomendamos rodar o Kairos dentro do WSL2 para a melhor experiência. Continuar pelo WSL? [S/n]" (default S, redireciona para `install.sh` dentro do WSL)
- [x] Em Windows sem WSL2: segue PowerShell nativo. Sem tentativa automática de instalar WSL
- [x] Valida pré-requisito obrigatório: **Claude Code** (CLI `claude` ou aba "Claude Code" do Claude Desktop). Se faltar, mostra instruções por SO e encerra
- [x] Pergunta opcional: "Quer também instalar Git? (necessário para contribuir com o framework Kairos; não necessário para uso normal)" — default não
- [x] Pergunta a pasta de instalação (default `~/kairos` / `%USERPROFILE%\kairos`)
- [x] Consulta tag semver mais recente via API GitHub e baixa o tarball — **sem `git clone`**. Usa `curl`+`tar` no .sh, `Invoke-WebRequest`+`Expand-Archive` no .ps1
- [x] Lê `manifest.yaml` do tarball e copia para a pasta de instalação **apenas** os arquivos relevantes: `owned_files` e arquivos com `owned_sections` (mesclando seções). Os arquivos de `sync_files` **não** são copiados, exceto `LICENSE` e as pastas vazias `.kairos-core/runtime/`, `data/`, `docs/` e `squads/` (se não existirem). O resto do tarball é descartado
- [x] Elicitação user-friendly (não exibir nomes de env vars cruas):
  - "Qual o seu nome ou apelido para identificar seus outputs no time? (pode mudar depois editando seu .env) →" → popula `KAIROS_INSTANCE_NAME`
  - "Quer sincronizar seus outputs para uma pasta compartilhada com o time? [s/N]" → se sim, explica brevemente (Drive Desktop, OneDrive, Dropbox), pede o caminho, chama internamente `*configure-cloud` da Story 7.4
  - Em Windows ao precisar elevar para criar symlink: "Para criar o atalho de sincronização, o instalador precisa de permissão de administrador por um momento. Vamos relançar com elevação? [S/n]"
- [x] Gera `.env` a partir de `.env.example` com os valores informados
- [x] **Não** registra hooks manualmente em `.claude/settings.json` — o hook SessionStart vem dentro da seção kairos-managed do `settings.json` framework-owned, é instalado automaticamente
- [x] Tela final com resumo do que foi feito + instruções claras de "como abrir": `cd ~/kairos && claude` (terminal) ou abrir a pasta no Claude Desktop (aba "Claude Code")

### Desinstalador (`uninstall.sh` + `uninstall.ps1`)

- [x] Banner ASCII de despedida + confirmação clara do que vai acontecer
- [x] Lê `.kairos-core/manifest.yaml`
- [x] Pergunta amigavelmente:

- [x] Walk bottom-up: deleta toda pasta vazia restante
- [x] Imprime resumo: X arquivos deletados, Y seções limpas, Z pastas removidas

### Decisões tomadas

- **Instalador não chama *configure-cloud inline:** o AC original previa "pede o caminho, chama internamente *configure-cloud". Optei por não tentar chamar o Claude Code de dentro do shell script (inviável em runtime de instalação sem sessão ativa). Em vez disso, o instalador exibe instruções claras de como configurar via `@kairos *configure-cloud` após abrir o projeto. O symlink de cloud sync é feito dentro do Claude Code onde o contexto está disponível.
- **Smoke tests pendentes por design:** exigem VM limpa ou ambiente isolado — não executáveis neste ambiente de desenvolvimento. Marcado como pendente, consistente com a decisão tomada na story 7.5.
- **install.ps1 + uninstall.ps1 sem frontmatter `kairos-owned`:** arquivos `.ps1` não suportam frontmatter YAML de forma nativa (não são markdown). O manifesto é a fonte autoritativa — frontmatter é complementar (verificado pelo *doctor apenas em `.md`). Correto por design.
- **`{INSTANCE}` no data-flow.md:** o padrão de output no data-flow.md estava desatualizado (sem o token `{INSTANCE}` da story 7.1). Atualizado junto com esta story por ser parte do requisito de *architecture.

### Ciclo de smoke test — Bugs corrigidos (2026-05-07)

Bugs identificados pelo usuário após smoke test real e corrigidos em segundo ciclo de implementação:

**Bug 1 — Instalador copiava sync_files errados**
`install.sh` e `install.ps1` copiavam `.gitignore`, `.gitkeep`, `README.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `CHANGELOG.md` para a pasta de instalação. AC 7.6 especifica explicitamente que de sync_files só vêm `LICENSE` e as pastas vazias. Corrigido: loop de sync_files reduzido a `"LICENSE"` em ambos os scripts; `.env.example` já tratado em bloco separado (correto).

**Bug 2 — Desinstalador não limpava `settings.json`**
`uninstall.sh` e `uninstall.ps1` só processavam arquivos `.md` em `owned_sections`. `.claude/settings.json` (type: `json_keys`, owned_keys: `[hooks]`) não era tratado — a chave `hooks` permanecia. Corrigido: `clean_managed_sections` (sh) e `Remove-ManagedSections` (ps1) agora lidam com `json_keys` via parse JSON + remoção das owned_keys.

**Bug 3 — Desinstalador não limpava `core-config.yaml`**
`.kairos-core/core-config.yaml` (type: `yaml_keys`, owned_keys: `[framework, runtime, versioning]`) não era processado. Corrigido: adicionado suporte a `yaml_keys` — remove blocos top-level por nome de chave, linha a linha, preservando conteúdo user-owned.

**Bug 4 — Desinstalador não limpava `.env.example`**
`.env.example` (type: `env_sections`) usa marcadores `# KAIROS-MANAGED-START/END` (não `<!-- -->`). O handler existente só tratava markdown. Corrigido: adicionado suporte a `env_sections` em ambos os scripts.

**Bug 5 — Symlinks impediam remoção de pastas vazias**
`data/outputs/` pode ser symlink (cloud sync via `*configure-cloud`). `find -type d -empty` e `rmdir` ignoram/falham em diretórios que contêm symlinks. Corrigido: adicionado passo de remoção de symlinks (exceto `data/outputs` se `KEEP_OUTPUTS=true`) antes do loop de pastas vazias, em ambos os scripts.

**Refatoração estrutural — `extract_owned_sections_full` (sh) e `Get-OwnedSectionEntries` (ps1)**
Para suportar os novos tipos de owned_sections, os parsers do manifesto foram estendidos para retornar `path|type|keys` (sh) e objetos `PSCustomObject` com `Path`, `Type`, `Keys` (ps1), em vez de apenas o path.

**Arquivos modificados neste ciclo:**
- `install.sh` — loop sync_files reduzido a LICENSE
- `install.ps1` — $syncFiles reduzido a LICENSE; .env.example em bloco separado
- `uninstall.sh` — extract_owned_sections_full; clean_managed_sections estendido; symlink removal
- `uninstall.ps1` — Get-OwnedSectionEntries; Remove-ManagedSections estendido; symlink removal
