## Objetivo

Empacotar o trabalho das stories 7.1–7.5 em uma experiência de instalação/desinstalação amigável para usuários não-técnicos. Instalador interativo cross-platform (Linux/Mac via `.sh`, Windows nativo via `.ps1`), download via tarball do GitHub (sem Git), elicitação user-friendly, opt-in para cloud sync, integração automática com `*configure-cloud`. Desinstalador respeita o manifesto: remove apenas framework-owned, preserva opcionalmente outputs e `.env`.

## Critérios de Aceite

### Instalador (`install.sh` + `install.ps1`)

- [ ] Banner ASCII de boas-vindas + texto humano explicando o que vai acontecer
- [ ] Detecta SO automaticamente (Linux/WSL/Mac em `.sh`; Windows em `.ps1`)
- [ ] Em Windows com WSL2 detectado: oferece "✓ WSL2 detectado — recomendamos rodar o Kairos dentro do WSL2 para a melhor experiência. Continuar pelo WSL? [S/n]" (default S, redireciona para `install.sh` dentro do WSL)
- [ ] Em Windows sem WSL2: segue PowerShell nativo. Sem tentativa automática de instalar WSL
- [ ] Valida pré-requisito obrigatório: **Claude Code** (CLI `claude` ou aba "Claude Code" do Claude Desktop). Se faltar, mostra instruções por SO e encerra
- [ ] Pergunta opcional: "Quer também instalar Git? (necessário para contribuir com o framework Kairos; não necessário para uso normal)" — default não
- [ ] Pergunta a pasta de instalação (default `~/kairos` / `%USERPROFILE%\kairos`)
- [ ] Consulta tag semver mais recente via API GitHub e baixa o tarball — **sem `git clone`**. Usa `curl`+`tar` no .sh, `Invoke-WebRequest`+`Expand-Archive` no .ps1
- [ ] Lê `manifest.yaml` do tarball e copia para a pasta de instalação **apenas** os arquivos relevantes: `owned_files` e arquivos com `owned_sections` (mesclando seções). Os arquivos de `sync_files` **não** são copiados, exceto `LICENSE` e as pastas vazias `.kairos-core/runtime/`, `data/`, `docs/` e `squads/` (se não existirem). O resto do tarball é descartado
- [ ] Elicitação user-friendly (não exibir nomes de env vars cruas):
  - "Qual o seu nome ou apelido para identificar seus outputs no time? (pode mudar depois editando seu .env) →" → popula `KAIROS_INSTANCE_NAME`
  - "Quer sincronizar seus outputs para uma pasta compartilhada com o time? [s/N]" → se sim, explica brevemente (Drive Desktop, OneDrive, Dropbox), pede o caminho, chama internamente `*configure-cloud` da Story 7.4
  - Em Windows ao precisar elevar para criar symlink: "Para criar o atalho de sincronização, o instalador precisa de permissão de administrador por um momento. Vamos relançar com elevação? [S/n]"
- [ ] Gera `.env` a partir de `.env.example` com os valores informados
- [ ] **Não** registra hooks manualmente em `.claude/settings.json` — o hook SessionStart vem dentro da seção kairos-managed do `settings.json` framework-owned, é instalado automaticamente
- [ ] Tela final com resumo do que foi feito + instruções claras de "como abrir": `cd ~/kairos && claude` (terminal) ou abrir a pasta no Claude Desktop (aba "Claude Code")

### Desinstalador (`uninstall.sh` + `uninstall.ps1`)

- [ ] Banner ASCII de despedida + confirmação clara do que vai acontecer
- [ ] Lê `.kairos-core/manifest.yaml`
- [ ] Pergunta amigavelmente:
  - "Quer preservar seus outputs em `data/outputs/`? [S/n]" (default sim)
  - "Quer preservar seu `.env` (caso reinstale)? [S/n]" (default sim)
  - "Quer apagar TUDO da pasta do projeto, inclusive arquivos que não são do Kairos? [s/N]" (default não)
- [ ] Para cada `owned_files`: deleta
- [ ] Para cada `owned_sections`: abre o arquivo, remove conteúdo entre marcadores `<!-- KAIROS-MANAGED-START/END -->` (markdown) ou os `owned_keys` (YAML/JSON). Se o arquivo ficar vazio ou só whitespace, deleta
- [ ] `sync_files`: removidos apenas se "apagar tudo"
- [ ] Walk bottom-up: deleta toda pasta vazia restante
- [ ] Imprime resumo: X arquivos deletados, Y seções limpas, Z pastas removidas

### Manifesto e UX

- [ ] Manifesto `.kairos-core/manifest.yaml` registra `install.sh`, `install.ps1`, `uninstall.sh`, `uninstall.ps1`, `.kairos-core/docs/install.md` como `owned_files`
- [ ] UX em todas as etapas: textos curtos, exemplos, opção de cancelar, validação de input com mensagens humanas (não jargão de sistema)
- [ ] Smoke tests:
  - **Cenário 1** — fresh install Linux/Mac: `curl -fsSL .../install.sh | bash` em VM limpa; usuário responde nome `teste`, opt-in cloud em `~/Drive/Kairos`; `cd ~/kairos && claude` → ativa `@email-writer *write 1`; confirma output em `~/Drive/Kairos/email-writer_emails-teste-YYYY-MM-DD.json`
  - **Cenário 2** — fresh install Windows nativo: executa `install.ps1`; validação de elevação para symlink funciona; usuário aceita relaunch
  - **Cenário 3** — fresh install Windows com WSL2: instalador detecta, recomenda; usuário aceita rota WSL
  - **Cenário 4** — uninstall preservando outputs: `data/outputs/` e `.env` permanecem; framework-owned removidos; CLAUDE.md tem seções KAIROS-MANAGED removidas, seções do usuário preservadas; pastas vazias deletadas
