## Objetivo

Os templates de contrato atuais têm linguagem jurídica genérica adequada para prestação de serviços TI/consultoria, mas insuficiente para serviços com características distintas. Esta story cria variantes especializadas dos templates e orienta o @contract-writer a selecionar a variante certa por tipo de serviço.

## Critérios de Aceite

- [x] Levantamento dos tipos de serviço prestados pelo usuário documentado em `squads/client-onboarding/data/kb.md` (ex: projeto fechado, retainer mensal, hora avulsa) — servindo como base para as variantes criadas
- [x] Pelo menos uma variante especializada criada em `squads/client-onboarding/templates/contract/` por tipo de serviço identificado, com cláusulas adaptadas (pagamento, vigência, rescisão, escopo) em relação ao template genérico existente
- [x] `squads/client-onboarding/README.md` atualizado com guia de "quando usar qual variante de contrato"
- [x] Guide do @contract-writer atualizado (bloco `kairos-custom` em `*draft`) para referenciar as variantes disponíveis e incluir critério de seleção por tipo de serviço

## Fora de Escopo

- Revisão por advogado ou assessoria jurídica — os templates continuam sendo rascunhos para revisão manual
- Templates em outros formatos além de Markdown
- Integração com ferramentas de assinatura eletrônica
- Cláusulas para contratos internacionais ou fora do direito brasileiro

## Dependências

- Story 4.3 Done ou In Review (squad scaffoldado, templates base e @contract-writer com persona funcional)

### Decisões tomadas

- **Estrutura `variants/` em vez de substituir templates genéricos:** as variantes ficam em subdiretório separado; os templates genéricos em `contract/` permanecem intactos. Isso preserva o princípio de "base estável — novas cláusulas são aditivas" do README original.
- **Cláusula 03 na variante projeto-fechado:** o genérico já era bom mas o projeto fechado ganha com tabela de entregáveis + critério de aceite + rodadas de revisão — criada variante dedicada. Retainer e hora-avulsa reutilizam o genérico (sem variante de escopo).
- **Cláusula 11 como cláusula extra (não substituição):** horas-incluidas e aprovacao-horas são cláusulas adicionais, não substituições — numeradas com `11-` e inseridas após Cláusula 2ª conforme convenção do README.md do template.
- **Bloco kairos-custom como Passo 0:** inserido antes do Passo 1 para que a seleção de variante ocorra antes do carregamento dos templates — fluxo mais natural para o agente.
