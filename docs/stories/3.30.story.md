## Objetivo

Corrigir o falso positivo que ocorre no Passo 4 do `*pre-push` a cada execução, e reposicionar a verificação de links quebrados para antes do commit — tornando o spot check acionável.

## Contexto

O Passo 4 atual verifica referências em arquivos `.md` modificados e sempre retorna falsos positivos nos epics. O motivo: ao extrair links relativos como `../stories/3.1.story.md` de arquivos em `docs/epics/`, o script resolve o path a partir de `docs/` (raiz), produzindo `/repo/stories/X.story.md` (inexistente) em vez de `/repo/docs/stories/X.story.md` (correto). O path deve ser resolvido a partir do diretório do arquivo que contém o link.

Além disso, o Passo 4 ocorre após o Passo 3 (commit). Links quebrados detectados pós-commit não têm como ser corrigidos antes de o commit acontecer — o check perde a utilidade preventiva. Reordenar resolve isso: o executor pode corrigir links antes de commitar.

## Critérios de Aceite

- [x] Em `kairos-pre-push.md`, a instrução do Passo 4 especifica que paths relativos em links internos devem ser resolvidos **a partir do diretório do arquivo que contém o link** (não a partir de `docs/` ou da raiz do repositório)
- [x] A instrução exemplifica o padrão correto: link `../stories/X.story.md` em `docs/epics/epic-N-*.md` → resolve para `docs/stories/X.story.md`
- [x] Em `kairos-pre-push.md`, o Passo 4 (verificação de referências quebradas) é reposicionado para **antes do Passo 3** (commit); os números dos passos são atualizados em consequência: verificação passa a ser Passo 3, commit passa a ser Passo 4
- [x] O checklist de cabeçalho da task reflete a nova ordem

## Fora de Escopo

- Alterar a lógica de BLOCK/não-BLOCK do spot check
- Tornar a verificação exaustiva (limite de 10 arquivos permanece)
- Corrigir outros tipos de falso positivo além da resolução de path relativo
- Modificar qualquer outro passo do `*pre-push`
