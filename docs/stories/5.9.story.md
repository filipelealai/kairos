## Objetivo

Corrigir o critério de skip do Passo 2b do push-dual para arquivos mistos (CLAUDE.md e core-config.yaml): em vez de usar `git log origin/main..filipe-instance -- <arquivo>` (que dispara reprocessamento sempre que qualquer parte do arquivo mudou, incluindo seções user-owned), comparar o conteúdo das seções managed que seriam escritas em `main` com o que já está em `main`. Se idêntico → skip real, sem sobrescrever.

## Contexto

Story 5.7 implementou o skip por commits para evitar reprocessamento desnecessário. Mas o critério é muito amplo: qualquer commit que toque o arquivo (mesmo só nas seções user-owned) dispara o reprocessamento. Identificado durante o push de 2026-04-19: CLAUDE.md foi reprocessado em `main` mesmo sem mudança nas seções kairos-managed, porque commits anteriores haviam tocado a seção user-owned ("Squads ativos").

## Critérios de Aceite

- [x] Para CLAUDE.md: o Passo 2b extrai os blocos managed de `filipe-instance:CLAUDE.md`, compara com o conteúdo atual de `main:CLAUDE.md`; se idêntico → skip com mensagem `→ skip: conteúdo managed sem mudança`
- [x] Para core-config.yaml: o Passo 2b constrói a versão de `main` (com placeholders) a partir de `filipe-instance:core-config.yaml`, compara com o conteúdo atual de `main:.kairos-core/core-config.yaml`; se idêntico → skip com mensagem `→ skip: conteúdo managed sem mudança`
- [x] O skip baseado em `git log` (story 5.7) é substituído pela comparação de conteúdo — não coexistem dois critérios
- [x] Quando há mudança real nas seções managed, o reprocessamento ocorre normalmente
- [x] O resumo final do Passo 2b reflete corretamente quantos arquivos foram reprocessados vs. pulados

## Fora de Escopo

- Outros arquivos mistos não declarados no manifesto (não existem no estado atual)
- Mudança no formato das seções managed do CLAUDE.md ou core-config.yaml
- Otimização do diff linha a linha — comparação de string completa é suficiente
