# Story 3.5 — Modelo de Stories para Instâncias: type, *update-squad, Framing e Avisos

**Epic:** 3 — Governança e Versionamento
**Status:** Done
**Complexidade:** G
**Tipo:** kairos-core
**Criada por:** @kairos
**Data:** 2026-04-15

---

## Objetivo

Resolver a contradição entre "stories = desenvolvimento do Kairos" e "squads/workers são instanciados pelo usuário": introduzir o campo `type: kairos-core | instance` no template de stories (onde `instance` cobre squads, workers e qualquer conteúdo instanciado), fazer `*new-squad` auto-criar a story ao final da elicitação, criar `*update-squad` para rastrear edições de squads, orientar o framing de `*new-story` e `*new-epic` para o uso padrão (instâncias), e exibir aviso proeminente sempre que o usuário trabalha com stories do tipo `kairos-core`.

---

## Critérios de Aceite

### Campo `type` e template

- [x] `story-template.md` atualizado — campo `type: kairos-core | instance` adicionado no cabeçalho (após `Complexidade`); comentário inline explicando a distinção: `kairos-core` = modifica o framework em si; `instance` = cria ou evolui squads, workers, agentes ou qualquer conteúdo instanciado pelo usuário
- [x] Para stories `type: kairos-core`: o template inclui bloco de aviso fixo imediatamente após o cabeçalho (ver formato na seção Aviso abaixo)

### *new-story: type, framing e aviso

- [x] `kairos-new-story.md` — pergunta `type` durante elicitação: "Esta story modifica o framework Kairos em si (kairos-core) ou cria/evolui um squad, worker ou agente (instance)? [instance]"; default é `instance`
- [x] `kairos-new-story.md` — framing orientado a instâncias: quando `type: instance`, a pergunta "O que precisa ser feito?" inclui exemplos de operações de instância (criar agente, configurar pipeline, adicionar task, expandir persona, configurar worker); quando `type: kairos-core`, remove os exemplos de instância
- [x] `kairos-new-story.md` — para `type: kairos-core`: exibe aviso proeminente imediatamente antes de criar o arquivo (ver formato na seção Aviso abaixo)
- [x] `kairos-new-story.md` — arquivo gerado inclui o bloco de aviso no início quando `type: kairos-core`

### Aviso kairos-core (formato canônico)

O aviso deve ser gerado e exibido no formato abaixo em todos os contextos aplicáveis:

```
⚠️  ATENÇÃO — MODIFICAÇÃO DO NÚCLEO DO KAIROS
────────────────────────────────────────────────────────────
Esta story modifica o núcleo do framework Kairos. Alterações
são livres (Kairos é open-source), mas podem impedir futuras
atualizações automáticas, e podem ser sobrescritas por
eventuais atualizações. Ao prosseguir, você estará fazendo
um fork local do Kairos. Continue com consciência — por conta
e risco do usuário.
────────────────────────────────────────────────────────────
```

### Persona @kairos: aviso persistente

- [x] Persona `kairos.md` — nova regra em `core_principles`: "Se a story ativa tem `type: kairos-core`, exibir o bloco de aviso no início de cada resposta enquanto trabalhar nela (criação, review, discussão)"
- [x] O aviso deve aparecer antes de qualquer conteúdo da resposta — não enterrado no meio do texto

### *new-squad: auto-criação de story

- [x] `kairos-new-squad.md` — ao final da elicitação e confirmação do scaffold, auto-executa `*new-story` com `type: instance` e epic pré-selecionado dentre o que o existente que mais encaixar, ou um novo é criado se nenhum bate ou nenhum existe; o usuário não precisa rodar `*new-story` manualmente
- [x] A auto-execução informa: "Criando story de implementação para o squad {nome}…" e gera a story com ACs pré-preenchidos derivados do elicitado: (1) persona `.claude/commands/kairos/agents/{id}.md` criada por agente; (2) tasks em `squads/{nome}/tasks/` implementadas com conteúdo real (não stubs); (3) scripts `src/agents/{id}.ts` por agente com script TS (se aplicável)

### *update-squad: novo comando

- [x] Nova task `kairos-update-squad.md` criada em `.kairos-core/tasks/`
- [x] A task elicita: qual squad, qual aspecto está sendo modificado (persona, task, pipeline, regra, integração), descrição da mudança
- [x] Cria story com `type: instance` e prefixo `update:` no título (ex: `update: cold-prospecting — nova regra de scoring`)
- [x] Persona `kairos.md` — comando `*update-squad {squad}` adicionado (visibility: full, quick)

### *new-epic: framing orientado a instâncias

- [x] `kairos-new-epic.md` — Pergunta 1 (Tema): adicionar nota orientadora: "O uso padrão do Kairos é criar e gerenciar squads, workers e agentes. Se este epic não for sobre o núcleo do framework, considere começar com *new-squad."
- [x] `kairos-new-epic.md` — Pergunta 3 (Critérios de Conclusão): exemplos atualizados para priorizar contextos de instância (squads, workers, agentes)

### *roadmap: visibilidade por type

- [x] `kairos-status.md` — stories `type: instance` e `type: kairos-core` exibidas distintamente no roadmap (prefixos visuais: `[instance]` e `[core]`)

### Docs

### Decisões tomadas

- **Template usa comentário HTML para o bloco de aviso:** o bloco de aviso em `story-template.md` ficou como comentário `<!-- -->` porque o template é base para geração — não faz sentido exibir o aviso em todas as stories, apenas nas `kairos-core`. A task `kairos-new-story.md` é quem decide quando inserir o aviso como texto real.
- **`kairos-new-squad.md` auto-executa sem perguntar:** a story de implementação passou de "pergunta se quer criar" para "auto-executa obrigatoriamente". Decisão alinhada com o AC da story 3.5 — o objetivo é que o usuário não precise rodar `*new-story` manualmente.
- **`kairos-new-story.md` versão bumped para 2.2.0:** reflete o escopo da mudança (nova pergunta, novos formatos, aviso) que justifica bump MINOR na versão da task.
