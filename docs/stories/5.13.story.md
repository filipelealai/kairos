## Objetivo

Atualizar `ownership.md` (L1) para documentar formalmente `sync_files` como terceira categoria do manifesto, tornando explícita a distinção semântica entre arquivos com ownership de update (`owned_files`, `owned_sections`) e arquivos apenas sincronizados sem esse ownership (`sync_files`).

## Critérios de Aceite

- [x] AC1: `ownership.md` menciona `sync_files` como terceira categoria do manifesto, ao lado de `owned_files` e `owned_sections`, com descrição do que cada uma representa
- [x] AC2: O texto explica a distinção semântica central: `owned_files`/`owned_sections` conferem ownership de update ao framework; `sync_files` garante sincronização de conteúdo, mas o usuário pode sobrescrever sem conflito com o updater
- [x] AC3: O formato de entrada em `sync_files` é documentado (`path`, `layer`, sem `sha256`) como diferencial em relação a `owned_files`
- [x] AC4: Nenhuma seção existente de `ownership.md` contradiz ou fica inconsistente com o novo texto sobre `sync_files`
