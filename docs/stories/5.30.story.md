Esta story modifica o núcleo do framework Kairos. Alterações
são livres (Kairos é open-source), mas podem impedir futuras
atualizações automáticas, e podem ser sobrescritas por
eventuais atualizações. Ao prosseguir, você estará fazendo

## Objetivo

Expurgar das tasks e templates do framework referências a ferramentas específicas (n8n, Google Sheets) apresentadas como se fossem o baseline esperado de qualquer squad — tornando-as, no máximo, exemplos ilustrativos opcionais entre outros, sem criar a impressão de dependência ou default.

## Contexto

Complementa a story 5.29 (que removeu exemplos cold-prospecting e hardcodes de stack TypeScript). Enquanto a 5.29 tratou de **o que** as ferramentas fazem (leads, campanhas, emails) e **como** os scripts são escritos (`.ts`), esta story trata de **quais ferramentas externas** o Kairos assume que o usuário usa.

O problema: n8n aparece como opção primária de fonte de dados, pergunta central de integração externa, destino padrão do último agente e campo fixo no manifesto do squad. Google Sheets aparece como campo fixo em `integrations`. Isso cria a falsa impressão de que todo squad Kairos naturalmente usa n8n e Google Sheets — quando na realidade qualquer automação, planilha ou API pode ser usada.

A correção não é remover n8n/Google Sheets completamente — são ferramentas comuns e mencioná-las como exemplos tem valor. A correção é mudar o **enquadramento**: de "qual é o papel do n8n?" (assume que tem n8n) para "qual sistema externo de automação você usa, se houver?" (n8n é um exemplo dentre vários).

## Critérios de Aceite

### kairos-new-squad.md

- [x] Pergunta 3.1 reescrita de forma neutra: opções genéricas ("Webhook externo", "API externa", "Arquivo local") — n8n pode aparecer entre parênteses como exemplo de plataforma, não como nome da opção
- [x] Pergunta 4.2 reescrita: "Este squad depende de algum sistema externo de automação ou integração?" (n8n como exemplo entre outros: Make, Zapier, scripts próprios)
- [x] Template `squad.yaml` gerado substitui `integrations: n8n: true | false, google_sheets: true | false` por uma seção de lista livre `integrations: []  # ex: n8n, google_sheets, slack, salesforce` com comentário orientador

### squad-template/squad.yaml

- [x] `integrations` substituído por lista livre com comentário: `# liste as integrações externas do squad (ex: n8n, google_sheets, salesforce)`

### squad-template/agents/agent-id.md

- [x] `handoff_to: "n8n se for o último"` substituído por `handoff_to: "{próximo agente — ou sistema externo se for o último}"` sem mencionar n8n como default

### squad-template/README.md

- [x] Diagrama de pipeline: `{sistema externo — ex: n8n}` mantém o `ex: n8n` mas fica claro que é exemplo, não expectativa — aceito como está se o contexto já for claramente ilustrativo; senão, ajustar para `{sistema externo ou integração — opcional}`

### agent-template.md

- [x] Seção `blocking` substitui exemplos cold-prospecting/webhook-específicos por placeholders genéricos: `HALT se: {fonte de dados externa indisponível}` e `HALT se: {sem dados para processar}`
- [x] `HALT se: erro no script TS — exibir stderr` substituído por `HALT se: erro no script — exibir stderr`

### kairos-architecture.md

- [x] Exemplo `JSON para n8n` substituído por `{formato} para {sistema externo}` ou exemplo neutro

### kairos-update-squad.md

- [x] Opção 6 reescrita: `Integração externa (API, webhook, automação)` — n8n removido da posição de destaque; pode aparecer entre parênteses como exemplo se necessário

### Critérios Transversais

- [x] Nenhum dos arquivos modificados trata n8n, Google Sheets ou qualquer outra ferramenta específica como campo obrigatório, opção default ou pressuposto estrutural
- [x] Ferramentas específicas, quando mantidas, aparecem entre parênteses como exemplos dentro de categorias genéricas (ex: "sistema de automação (ex: n8n, Make, Zapier)")
- [x] Um usuário instalando o Kairos com Make, Zapier, scripts próprios ou sem automação alguma não recebe elicitações ou templates que assumem n8n

## Fora de Escopo

- Remover todas as menções a n8n/Google Sheets dos arquivos — exemplos ilustrativos são válidos e bem-vindos
- Atualizar squads de instância (cold-prospecting, ops) — user-owned
- Personas dos agentes em `.claude/commands/kairos/agents/` — escopo de outra story
- Criar integrations registry ou sistema de plugins (melhoria futura separada)
