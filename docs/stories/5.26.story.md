⚠️  ATENÇÃO — MODIFICAÇÃO DO NÚCLEO DO KAIROS
────────────────────────────────────────────────────────────
Esta story modifica o núcleo do framework Kairos. Alterações
são livres (Kairos é open-source), mas podem impedir futuras
atualizações automáticas, e podem ser sobrescritas por
eventuais atualizações. Ao prosseguir, você estará fazendo
um fork local do Kairos. Continue com consciência — por conta
e risco do usuário.
────────────────────────────────────────────────────────────

## Objetivo

Remover os hardcodes de stack TypeScript da task `kairos-architecture.md`, fazendo o `*architecture` descobrir runtime, arquivos de dependência e scripts de agentes a partir do que está declarado em `docs/scope.md`, e tratar `agent-standards.md` com a mesma lógica simétrica já usada para `data-flow.md` no modo framework.

## Critérios de Aceite

- [ ] `*architecture` modo framework não referencia `package.json` nem `src/agents/*.ts` diretamente — toda informação de stack é lida de `docs/scope.md` (seção Stack) e dos caminhos declarados nela
- [ ] Se `docs/scope.md` não tiver seção Stack, `*architecture` exibe aviso explícito e prossegue com checks limitados (sem assumir nenhum default de runtime ou linguagem)
- [ ] Scripts de agentes são descobertos via declaração em `docs/scope.md` ou `squads/{squad}/squad.yaml`; se nenhum path estiver declarado, o check é marcado ⚠️ "Scripts não declarados no escopo" em vez de assumir `.ts`
- [ ] `*architecture` modo framework inclui verificação de `.kairos-core/docs/agent-standards.md` com os mesmos checks já aplicados a `data-flow.md`: comparar docs vs implementação, marcar ✅/⚠️/❌
- [ ] Se divergências em `agent-standards.md` forem encontradas, `@kairos` exibe diff proposto e aguarda confirmação explícita antes de atualizar — comportamento idêntico ao de `data-flow.md`
- [ ] Relatório do modo framework inclui seção `━━━ AGENT STANDARDS ━━━` no output, ao lado de `━━━ DATA FLOW ━━━`
- [ ] `kairos-architecture.md` documenta explicitamente a lógica de descoberta de stack (sem hardcodes) e o tratamento simétrico de `agent-standards.md`

## Fora de Escopo

- Modo squad (`*architecture {squad}`) não muda — já descobre agentes dinamicamente via `squad.yaml`
- Não criar nem alterar o conteúdo de `docs/scope.md` ou `.kairos-core/docs/agent-standards.md` — essa story só muda como `*architecture` os usa
- Não implementar mecanismo de registro de stack em `docs/scope.md` — responsabilidade do `*prd`
- Não alterar checks de consistência de tasks, personas ou handoffs — apenas stack e agent-standards

## Dependências

- 5.24 (Documentar Posição Stack-Agnóstica do Kairos) — idealmente Done antes, pois garante que `docs/scope.md` tenha seção Stack populada para o novo fluxo ler
- 5.25 (Fix L1: src/ É User-Owned) — clarifica que `src/` não é domínio do framework, alinhando com a remoção do hardcode `src/agents/*.ts`
