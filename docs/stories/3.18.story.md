## Objetivo

A story 3.15 removeu o `(story {id})` das entradas do CHANGELOG, mas introduziu um prompt ao usuário pedindo uma descrição manual — o que é frágil e ainda pode conter referências de instância. O CHANGELOG é um artefato do framework: sua descrição deve ser derivada automaticamente do que de fato mudou no framework (arquivos, tasks, rules), sem interação do usuário e sem nenhuma referência à camada de instância (story IDs, títulos de story, dados do usuário).

## Critérios de Aceite

- [x] O prompt `Descreva a mudança para o CHANGELOG` é removido do step 2.d de `kairos-pre-push.md` (MINOR/MAJOR) e da nota na seção PATCH (step 2 item 4)
- [x] Em seu lugar, o step 2.d deriva a descrição automaticamente, na seguinte ordem de prioridade:
  1. **Git diff**: identificar quais arquivos framework (listados em `.kairos-core/manifest.yaml` → `owned_files`) foram modificados ou adicionados desde o último commit; formatá-los como `{arquivo1}, {arquivo2}: {verbo}` onde `verbo` é `adicionado` (arquivo novo) ou `atualizado` (arquivo modificado)
  2. **Execution Log da story**: se a story ativa tem seção `## Execution Log` → `### O que foi feito`, usar o primeiro bullet — mas **sanitizado**: remover qualquer substring que corresponda a `\(story \d+\.\d+\)` ou `story \d+\.\d+` ou títulos entre aspas de stories

## Notas de Implementação

O passo de derivação deve acontecer **dentro do step 2.d**, antes de escrever o CHANGELOG. Algoritmo sugerido:

```
1. git diff HEAD --name-only  (arquivos modificados não commitados)
   + git diff --cached --name-only  (staged)
   → union dos dois conjuntos

2. Cruzar com owned_files do manifest.yaml:
   → manter apenas os que estão no manifesto (são framework)
   → separar em: novos (status A) vs modificados (status M)

3. Se lista não vazia:
   → descrição = "{arquivo1}, {arquivo2}: adicionado|atualizado"
   → preferir versão curta (basename sem path completo quando óbvio)

4. Se lista vazia E story tem Execution Log:
   → pegar primeiro bullet de "### O que foi feito"
   → sanitizar: remover "(story X.Y)", "story X.Y", e títulos entre aspas
   → usar como descrição

5. Se ambos falharem:
   → "ajuste de instrução no framework"
```
