# Story 1.2: Pipeline de Agentes — Análise, Scoring, Nichos e E-mails

**Status:** Done
**Escopo:** cold-prospecting
**Epic:** 1 — Infraestrutura de Dados

---

## Contexto

Com o webhook de leads funcionando, foi necessário construir os quatro agentes do pipeline de prospecção: análise de campanha, pontuação de leads, classificação de nichos e geração de e-mails personalizados.

A decisão arquitetural principal foi usar Claude Code como motor dos agentes (slash commands / personas ativáveis via `@nome`) em vez de scripts TypeScript chamando a Anthropic SDK diretamente — exceto para computação pura (scoring, stats), que permanece como TypeScript sem AI.

---

## O que foi feito

1. `src/agents/campaign-analyst.ts` — computa métricas localmente, salva relatório Markdown
2. `src/agents/lead-scorer.ts` — algoritmo de scoring multidimensional, salva CSV ranqueado
3. `src/agents/niche-classifier.ts` — identifica atividades sem cobertura, classifica com Claude API em lotes
4. `src/agents/email-writer.ts` — gera e-mails via Claude API (substituído como motor principal pelo comando `@email-writer`)
5. Quatro personas completas em `.claude/commands/kairos/agents/`
6. Sistema de handoffs em `.kairos-core/runtime/handoffs/`
7. Tasks em `.kairos-core/tasks/` com formato YAML frontmatter
8. Rules cross-cutting em `.claude/rules/`
9. Squad `cold-prospecting` em `squads/cold-prospecting/`

---

## Riscos

| Risco | Mitigação |
|-------|-----------|
| E-mails genéricos/robóticos | Checklist explícito na task write-emails.md + auto-check do 1º parágrafo |
| Emails para endereços suspeitos | Detecção de domínio + flag `email_suspeito` |
| Webhook indisponível | Blocking explícito em todos os agentes |
